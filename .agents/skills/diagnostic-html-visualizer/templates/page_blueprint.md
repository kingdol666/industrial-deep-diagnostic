# Page Blueprint

这个模板规定页面结构，不规定具体文案。

## Recommended File Output

- Default: `<run_dir>/diagnostic-report.html`

## Runtime Readiness Banner

页面顶部或首屏附近必须有一个轻量状态区，显示：

- 图表引擎加载状态
- 3D 引擎加载状态
- 交互模块初始化状态

如果交互组件失败，也要让用户知道页面仍可阅读，但当前处于降级模式。

## Page Outline

### 0. Hero / Executive Snapshot

- 页面标题
- 场景副标题
- 主结论一句话
- 一句“为什么先看这个结论”
- 关键标签：诊断类型 / Judge 评分 / 焦点产品 / 样本量 / 异常工段
- 三到四个摘要卡
- 一段“如何阅读此页”的极短说明

### 1. 背景与动态建模

- 背景说明：产线、产品、目标缺陷、分析范围
- 本体模型卡片：设备、工段、信号、质量指标
- 产线流程可视化
- 3D 产线模型
- 异常位置高亮与标注
- 3D 模块状态说明（已启用 / 降级）

### 2. 诊断流程概括

- 诊断步骤流程带
- “看似相关 -> 校验后重排”的收敛图
- 对 Simpson 悖论、分层分析、去趋势的通俗解释
- 每个步骤必须有一句白话总结

### 3. 数据图表与解释

建议按“最关键 -> 次关键”排列：

1. 时间对齐图
2. 全局 vs 产品内 vs 去趋势后
3. 温区 / 扭矩剖面
4. 相关性鲁棒性
5. 分布图 / 假说评分图

每张图配三行解释：

- 图上看到什么
- 数据说明什么
- 业务含义是什么

主内容区建议控制在 3-5 张核心图；更多图进入折叠区、附录区或扩展证据区。

### 4. 证据链与因果溯源

- 主导结论卡
- 协同证据卡
- 被削弱假说卡
- 被排除假说卡
- 总证据链图
- 行动建议
- 局限性与下一步验证

每张结论卡建议固定结构：

1. 这条结论是什么
2. 最强可视化证据是什么
3. 最强推理证据是什么
4. 为什么不是别的原因
5. 下一步如何验证

## Minimum Chart Set

如果 JSON 足够，至少重建以下图中的三种：

1. 批次时序对齐图
2. 相关性对比图
3. 18 辊分区剖面图
4. 假说证据评分图
5. 因果证据链图

其中至少一个必须是真正由 ECharts 成功渲染的交互式图表；不能全部退化为静态占位。

## 3D Module Rules

3D 模块以“帮助理解工段与异常位置”为目标，不追求重建真实 CAD。

### Geometry Mapping

- 工段：长方体平台
- 辊组：圆柱体
- 物料路径：折线或发光曲线
- 异常点：红橙色高亮、发光圈、悬浮标记

### Interaction

- 至少支持旋转和缩放
- 初始镜头要能直接看到异常工段

## Tone

- 专业但通俗
- 讲事实，不渲染
- 用户看完后应能复述“结论是什么、为什么、下一步做什么”

## Acceptance Lens

一个合格页面应当让用户快速回答：

1. 结论是什么
2. 问题在哪里
3. 最强证据是什么
4. 为什么不是别的原因
5. 下一步做什么
