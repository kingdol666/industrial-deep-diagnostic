# Report Checklist

按此清单验证最终诊断报告的质量和完整性。

## 实事求是检查（最高优先级 — 在结构检查之前执行）

- [ ] **每个结论都有证据来源标注** — `[OBSERVED]`、`[MEASURED]`、`[VLM_OBSERVED]`、`[HYPOTHESIS]`、`[INFERENCE_GAP]`
- [ ] **没有编造物理机制** — 如果 ontology/rag 中没有对应失效模式，有标注 `[PHYSICS_UNVERIFIED]`
- [ ] **没有选择性报告** — 如果 `diagnosis.json` 返回 `COMPETING_SET`，所有竞争假设都出现在报告中
- [ ] **没有用模糊词掩盖不确定性** — 报告中搜索不到"可能存在"、"有一定关联"、"值得关注"等无信息量表述
- [ ] **证据不足时明确说了"无法确定"** — 如果置信度 <70 或诊断类型为 `NEEDS_DATA`，第3节有诚实声明
- [ ] **每个证伪条件具体可执行** — 没有"需要更多数据"这类笼统表述
- [ ] **统计术语都有白话翻译** — 每个 r/p/ρ/CCF 旁边配了人话说明
- [ ] **物理机制都有类比/比喻解释** — "就像______一样"

## 对齐图展示检查（第2节 — 核心证据）

- [ ] **所有 per-product overlay 图已嵌入** — `fig_vlm_temporal_overlay_focus_*.png` 和 `fig_vlm_temporal_overlay_prod_*.png`
- [ ] **重点产品（异常率最高）的对齐图排在前面**
- [ ] **每张对齐图有三段式解读**:
  - [ ] 图上看到了什么（VLM 视觉观察）
  - [ ] 统计怎么说（统计验证交叉引用）
  - [ ] 物理上说得通吗（ontology 物理含义）
- [ ] **每张对齐图回答了核心问题**: "哪个工艺参数的波动导致检测数据异常？"
- [ ] **对齐图中如果没有清晰关联，明确说了** — "该产品中未观察到工艺参数与检测指标的清晰时间对齐模式"
- [ ] **有跨产品对比分析** — 区分产品级问题 vs 工艺级问题
- [ ] **有对齐图分析的总体结论** — 从所有对齐图中提炼的核心发现

## 结构完整性（9节正文 + 附录）

- [ ] 9个正文章节全部出现，顺序正确
- [ ] 报告页眉含场景、产品/批次、日期、运行ID、Judge评分
- [ ] 报告开头有"实事求是声明"
- [ ] 附录（A-E）均已出现
- [ ] **第1节（执行摘要）在一页纸内，可2分钟读完**
- [ ] **第2节（对齐图分析）是报告中最核心的证据章节**
- [ ] **第5节（关键发现详解）是报告中最扎实的章节**

## 执行摘要检查（第1节 — 最重要）

- [ ] 回答了五个问题: 发生了什么 / 为什么会发生 / 影响多大 / 应该怎么做 / 多大把握
- [ ] 包含至少5个具体数字（统计量、变化幅度、业务损失、置信度分数）
- [ ] 语言让非技术人员可以完全理解
- [ ] 关键发现用粗体突出
- [ ] 推荐行动有优先级 + 预期效果 + 时间 + 成本估算

## 证据链推导（第5节 — 每个关键发现）

- [ ] 每个存活假说都有独立的小节（5.1, 5.2...）
- [ ] 每个小节包含完整推导: 观测→对齐图→统计→物理→排除→把握
- [ ] 每个统计术语配了白话翻译（表格"白话翻译"列）
- [ ] 物理机制有用类比/比喻解释
- [ ] 每个发现至少引用2张图
- [ ] 每个发现有其5因子置信度分解
- [ ] 每个发现有可操作的证伪条件

## 外行可读性检查（贯穿全报告）

### 必须做到
- [ ] 关键结论在前三段就出现（不藏到后面）
- [ ] 复杂统计概念配白话翻译（"1000次里只有不到1次是巧合" = p<0.001）
- [ ] 物理机制有用日常类比解释（"就像______一样"）
- [ ] 每个重要数字说明了业务含义（"这意味着______"）
- [ ] 语言没有任何"AI腔"

### 必须删除
- [ ] "值得注意的是"、"综上所述"、"可以看到"、"显然" — 全部删除
- [ ] "基于本次数据分析，我们认为" — 替换为具体观测引用
- [ ] "经过全面深入的诊断分析" — 已删除
- [ ] "可能存在一定的关联性" — 替换为具体统计量
- [ ] "从某种程度上"、"大体上"、"较为" — 全部删除
- [ ] "强烈建议"、"高度重视" — 替换为"P0行动: [具体操作]"
- [ ] 任何"AI分析"、"模型判断"、"算法判断" — 已删除

### 数字密度
- [ ] 第1节（执行摘要）至少5个具体数字
- [ ] 第2节（对齐图分析）每个产品的解读至少3个具体数字
- [ ] 第5节每个发现子节至少5个具体数字
- [ ] 没有出现"显著"、"相关"、变化"而无具体数字的情况

## 图片相关

- [ ] `plot_manifest.json` 中的每张图都在报告中出现
- [ ] 每张图使用 `![title](03_figures/filename.png)` 嵌入
- [ ] 对齐图（第2节）每张都有完整三段式解读
- [ ] 其他图（第5节和第7节）每张都有: 一句话描述 + 视觉发现 + 统计交叉验证 + 诊断含义
- [ ] 第5节每个发现至少引用2张不同的图
- [ ] 图像的"诊断含义"明确写出支持哪个结论
- [ ] 第1或第2节至少嵌入1张最关键的趋势图
- [ ] 没有空图或无法显示的图片

## 置信度与不确定性

- [ ] 第1节有白话版的置信度说明
- [ ] 第5节每个发现有其5因子分解
- [ ] 每个因子的得分有白话说明（为什么给这个分）
- [ ] 第9节诚实披露了诊断的盲区和局限
- [ ] 每个结论有可操作的证伪条件（不只是"需要更多数据"）

## 行动方案（第8节）

- [ ] P0/P1/P2 优先级正确分类
- [ ] P0 行动: 有具体操作 + 量化预期效果 + 验证方法 + 时间估算 + 成本估算
- [ ] 每个行动有证伪条件（行动无效意味着什么）
- [ ] 附有行动效果监控表（监控指标 + 基线 + 目标 + 频率）

## 内容准确性

- [ ] 报告中的统计数字与 `feature_summary.json` 一致
- [ ] 报告中的时间窗口与 `anomaly_report.json` 一致
- [ ] 报告中的对齐图解读与 `visual_analysis.json` 中的 VLM 观察一致
- [ ] 报告中的置信度与 `confidence.json` 一致
- [ ] 假设ID 与 `diagnosis.json` 一致
- [ ] diagnosis_type 与 `diagnosis.json` 一致
- [ ] 如果 VLM 观察与统计结果不一致，报告中已显式披露
- [ ] run_summary.json 与报告内容一致

## 自包含性

- [ ] 不需要读取其他文件即可理解报告内容
- [ ] 所有关键图表嵌入在报告中
- [ ] 所有缩略语在首次出现时解释
- [ ] 附录中的表格在正文中被引用
