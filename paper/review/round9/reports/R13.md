### 1.3 §5 C1: keyword calibration, timing, and sensitivity (independent recomputation)

I reproduced the sensitivity analysis from first principles:
- Pre-revision keywords from `git show 221d061~1:scripts/benchmark/cases/benchmark_cases.json`;
  calibrated from the current file (pinned at 221d061).
- Rebuilt the grader's matching corpus exactly per
  `scripts/benchmark/zcode_direct_pipeline.mjs:373-390` (`primary_finding` + surviving hypotheses'
  name / flattened `physical_logic_chain` / `supporting_evidence` / `ontology_data_physics_proof`,
  lowercased substring matching) over the canonical run dirs referenced by
  `results/benchmark/gradings/*.json`.
- tep_d01: pre-revision hits **[]** → calibrated hits **["配比"]** — the sole hit is the added
  synonym, exactly as the paper states. tep_d03: pre-revision **["温度"]** (the deleted generic
  token) → calibrated **[]**. Aggregates: Top-1 5/9 pre vs 6/9 calibrated; top-k 8/9 under both.
  My recomputation reproduces `results/benchmark/keyword_sensitivity.json` cell for cell. **Match.**

Timing disclosure (C1, p.24-25) — **the one substantive mismatch found in this review.** The paper
says "the canonical pipeline executions precede a uniform keyword calibration … applied once,
uniformly, before the v2 final aggregation (the journal records that one pre-calibration grading of
IDV1 existed and was superseded)---not per scenario after seeing results." The released journal
(`results/benchmark/journal.jsonl`) shows:
- 2026-09-14T20:06:33Z (= 09-15 04:06 +0800): old d01 run graded under **pre-revision** keywords,
  top1 = false, kw = [] — this is the disclosed superseded grading. ✓
- 2026-09-14T20:09:48Z (= 04:09 +0800): same run re-graded under **calibrated** keywords (hits
  进料配比/配比/a:c/stream 4). So the calibration was applied to the working tree between these two
  entries, i.e. ~04:07–04:09 +0800 on 09-15.
- The canonical re-executions `202609150453290` (skab valve, 04:53:29 +0800) and `202609150454126`
  (tep_d01, 04:54:12 +0800) therefore started ~45 min **after** the calibration was in effect; the
  first canonical d01 grading is 2026-09-15T06:22:49Z (= 14:22 +0800), still before commit 221d061
  (2026-09-15 19:20:18 +0800, `git log -1 221d061`); the released grading files were regenerated
  09-16 17:43 (+0800), after the commit.

So the accurate ordering is: 7 of 9 canonical fault executions precede the calibration; the two
09-15 re-executions (including the one scenario whose Top-1 verdict *depends* on the calibration)
follow it; the commit pinning follows even the first canonical grading. "Executions precede
calibration" is false for tep_d01 — the sentence must be rewritten to match the journal. The
mitigations are real and released (truth isolation keeps keywords out of inference; the sensitivity
artifact quantifies the effect at −1 Top-1; the superseded run also hits under calibrated keys, so
the re-execution was not necessary for the hit), which is why this is a precision correction rather
than a credibility failure. See MUST-FIX 1 and 2.

## 3. Summary judgment

This is the rare system paper where every one of the ~25 numbers I recomputed or traced matches the
released artifacts, the negatives are disclosed at the same volume as the positives (bare-LLM 9/9
beating the pipeline's 6/9 is in the abstract), and the uncertainty story (wide Wilson intervals,
single-execution caveat, within-era stability, seeded re-test draw, deterministic-layer-only
byte-reproducibility) is methodologically sound. The blocking issue is narrow: one sentence of the
C1 timing narrative ("canonical pipeline executions precede … calibration") is contradicted by the
project's own journal for exactly the scenario whose headline count depends on the calibration, and
the 6/9 headline in the abstract/conclusion does not carry the 5/9 pre-revision qualifier that §5
C1 itself establishes. Both are textual fixes; the data behind them is already released.

## 4. Findings

### MUST-FIX

1. **[p.24-25, §5 C1] Timing-ordering sentence contradicted by the released journal.** Paper:
   "the canonical pipeline executions precede a uniform keyword calibration." Journal: keyword
   switch between 2026-09-14T20:06:33Z (d01 graded, pre-revision, top1=false) and 20:09:48Z
   (calibrated), i.e. 04:07–04:09 +0800 on 09-15 — *before* the canonical re-executions
   `202609150453290` (04:53) and `202609150454126` (04:54); commit 221d061 (19:20:18 +0800)
   postdates even the first canonical grading (14:22 +0800). Rewrite the sentence to state the
   actual order (early batch → calibration → two re-executions → canonical gradings → pinning
   commit → final aggregation).
2. **[p.1-2 abstract, p.5 contribution 4, p.60 conclusion] Headline 6/9 lacks the pre-revision
   qualifier.** §5 C1 (and the released `keyword_sensitivity.json`) establish Top-1 = 5/9 under
   the pre-revision keys; the abstract/conclusion should carry "(5/9 under the pre-calibration
   keyword sets, §5)" wherever 6/9 is headlined, so the headline survives the paper's own
   sensitivity analysis.
3. **[p.19, §4 elimination contract] `revival_condition` mislisted as machine-checked.** The clause
   "with each elimination additionally recording a revival condition" is appended to the
   machine-checked list, but `schemas/diagnosis_schema.json` requires only
   {hypothesis_id, exclusion_type, specific_evidence} — revival_condition is optional at the gate
   and agent-enforced (SKILL.md Phase 5). Move it to the agent-applied side of the sentence.

### SHOULD-FIX

1. [p.24, §5 C1] "over-generic single-character tokens removed" is imprecise: removed generics
   include two-character tokens (温度) and the retained sets still include a single-character 阀
   (skab_valve1_1); describe the rule, not the character count.
2. [p.19, §4] State explicitly that the 0.65 INDISTINGUISHABLE and 0.50 PARAM_AMBIGUITY caps are
   agent-documented only; the machine R4 gate enforces a flat 0.70 for all COMPETING_SET.
3. [p.35, Fig 3(a)] Move the printed "0/2" off the sky-blue top-k segment (or label both segments)
   so the Top-1 fraction is not misread.
4. [p.30 Table 3 / §6.1] Determined-verdict precision (6/6) is conditional on the DETERMINED
   selection and shares its events with Top-1; note the non-independence so the two CIs are not
   read as independent evidence.
5. [p.47 Table 7, §7.5] Clarify that IDV1's "R2" is the canonical graded execution itself
   (202609150454126), i.e. its stability pair is (superseded 09-14 run, canonical run) — true for
   the row but not obviously "an additional fresh re-execution".
