# R14 — Industrial-Informatics Systems Review (Round 9, blind)

Reviewer scope: §2–§3 architecture truthfulness and clarity — skills-vs-agents dispatch, sub-agent
inventory and VLM placement, Step 3.5 / Phase 5.5 mapping, parallel-step claim, CP-1..CP-9
predicates, module-contract filenames vs released run directories, 14-engine layer with typed
400/409 errors, repair governance, RAG-layer claims, model assignment. All claims verified against
the repository, not taken from the paper.

---

## 1. Overall assessment

The paper's systems description is, with two localized exceptions, **accurate to an unusual
degree**. I traced every checkable §2–§3 statement to the released code and run artifacts: engine
count and error codes, contract function names, checkpoint predicates, artifact paths and
directory prefixes, the Phase 5.5 nesting, the parallel-step rule, the repair counters, and the
run-by-run RAG engagement narrative (including the unflattering parts: the canonical TEP run whose
RAG artifact records `rag_available=false`, and the SKAB runs with no RAG artifact at all). The
paper does not embellish the system — it discloses degradations, silent bypasses, and the mock
engine honestly. The two exceptions are one-line precision errors in §3.1 (skill-package contents;
VLM dispatch phrasing) that contradict the released skill tree and must be fixed. Layout of the
§3 float pages (15, 17) is loose for print. Verdict: minor revision.

## 2. Detailed findings by focus area

### 2.1 Skills-vs-agents dispatch (§3.1, p.9–10; Fig. 1, p.13)

- "18 skill packages executed by 14 specialised agents" — **TRUE**: `.claude/skills/` contains
  exactly 18 packages; `.omp/agents/` contains exactly 14 agent definitions.
- "the diagnostic path (Steps 2–8.5) dispatches eight specialist sub-agents — context-builder,
  data-processor, diagnostician, judge, report-reviewer, reporter, html-visualizer, html-reviewer"
  — **TRUE**: the orchestrator sub-skill map (`.claude/skills/industrial-analysis-auto/SKILL.md`
  79–89) dispatches exactly these eight; report-reviewer serves both Step 5b and Step 7.
- `SKILL_PATH`/`RUN_DIR` path-passing dispatch and artifact-only inter-agent communication —
  **TRUE**: dispatch prompts in SKILL.md 96–160 carry only paths and directives.
- **MISMATCH (must fix)** — "each package is a directory of a protocol checklist
  (`references/agent-protocol.md`), JSON Schemas … and validation scripts" (p.10, §3.1 second
  clarification): 5 of 18 packages have **no** `references/agent-protocol.md`
  (industrial-analysis-auto — the orchestrator itself has no `references/` directory —
  industrial-data-preprocessor, darwin-skill, diagnostic-html-visualizer, rag-knowledge-builder).
  All eight *dispatched sub-agent* packages do have it, so the correct scoping exists; the word
  "each" makes the sentence false as written.
- **IMPRECISE (should fix)** — "with the VLM visual analyzer running inside the data-processor's
  Phase 5.5 **rather than as a separate dispatch**" (p.10): the released skill says the opposite
  in its own words — "VLM visual analysis is dispatched via a separate Agent() call to the
  vlm-visual-analyzer Agent" (`industrial-data-processor/SKILL.md:78`, dispatch block 131–137).
  What is true is that it is not one of the *orchestrator's* eight dispatches; it is a nested
  dispatch by the data-processor. Rephrase (e.g. "rather than as a separate orchestrator
  dispatch") to survive an auditor. The module-contracts table row "vlm-visual-analyzer (inside
  data-processor Phase 5.5)" is accurate.

## 3. Verdict rationale

Everything I could falsify, I tried to falsify: engine count, error codes, checkpoint predicates,
artifact paths, RAG artifacts, event logs, caps, weights, phase numbering. The §2–§3 systems
account survived all of it except two sentences in §3.1. Those two sentences are cheap to fix but
must be fixed — this paper's entire credibility strategy is "every systems statement is checkable
against the released tree", so its own checkable statements must be exactly right. With those
edits and the float-page cleanup, this is a publishable, unusually honest systems paper.
