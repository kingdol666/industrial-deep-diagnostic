## 4. AEI assessment

Strengths: (i) the system description is verifiably true of the released code — the census, the CP
table, the caps, the marker census, the chronology, and the RAG accounting all reproduce from
artifacts without a single mismatch found; (ii) the execution-form disclosure (inline, no spawn
tool, serialized 5a/5b, shared-session corollary) is candid, per-run evidenced, and repeated where
it matters; (iii) the ablation that shows a bare same-model call scoring 9/9 against the pipeline's
6/9 is a model of honest negative reporting; (iv) keywords are shown to be grading-side only with a
replayable sensitivity analysis.

Weaknesses (all presentation-level): §2.1's "three scoping clarifications" is a ~450-word single
paragraph that carries the entire architecture scoping and should be split or tabulated; the
sonnet-tier model assignment of the three optional-layer agents is never mentioned (harmless but
easy to state); Fig 3(a)'s hatched SKAB bar vs its 0/2 fraction needs a second look; Table 5's
"every later canonical grading uses the calibrated set" is strictly true but the pre-switch batch
did grade two canonical run directories at 20:06:32Z (outcomes unchanged; disclosed as superseded
in the C1 prose) — one clarifying clause in the table would make the table self-contained; the
compiled paper runs to 75 pages including appendix and tables, at the upper bound of what AEI
readers tolerate.

No blocking defect was found in any area of my focus.
