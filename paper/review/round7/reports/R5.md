## 2. §4 formalization vs. enforcing code and released confidence.json

**Ceilings.** Eq. (1): CS 0.70 / INDIST 0.65 / anti-osc 0.50 / none for det+nd.
- `.claude/skills/industrial-diagnostician/SKILL.md:94` ("INDISTINGUISHABLE → confidence_ceiling ≤ 65") and `:106` ("INDISTINGUISHABLE ≤ 65, COMPETING_SET ≤ 70, [PARAM_AMBIGUITY] ≤ 50") — match.

The five reason codes listed in §4.1 match the schema enum verbatim: `.claude/skills/industrial-diagnostician/schemas/confidence_schema.json:121`.
- Observed CS band 0.58–0.65 is consistent with the 0.65 subclass cap inside the 0.70 cap.

**Five-factor weights 25/25/20/20/10.** Enforced at `.claude/skills/industrial-diagnostician/scripts/diagnostic-quality-check.mjs` (factorMax map: statistical_strength 25, physical_plausibility 25, temporal_evidence 20, absence_of_confounds 20, symptom_completeness 10; per-factor over-max warning). Released IDV4 `confidence.json` H1: scores 22/22/18/18/8 against maxes 25/25/20/20/10, overall 0.75 after the DIRECT_MEASUREMENT cap — consistent with c ≤ min(five-factor = 0.88, 0.75). Match.

**Elimination contract.** ≥2 eliminations: critical check `INSUFFICIENT_ELIMINATED` at `diagnostic-quality-check.mjs:66-69`; COMPETING_SET ≥2 survivors at `:75`. Exclusion confidence ≥ 0.90 is schema-enforced: `schemas/diagnosis_schema.json:340` (`"exclusion_confidence": {"type": "integer", "minimum": 90, "maximum": 100}`); revival condition in SKILL.md Phase 5 (line 95). Match. *Caveat:* the headline inequality |X_i| > |E_i| itself is protocol text followed by the agent, not a directly machine-checked predicate; what is machine-checked is the count floor, the schema floor on exclusion confidence, and evidence citation (rubric R2: `eliminated_with_evidence`, verified in `rubric.json`).

**Formalization defect (the one real weakness in §4).** Eq. (1) is written as a function of the verdict state v, but its three binding cases condition on three different variables: v = CS (0.70), a *subclass* of CS labelled by indistinguishability (0.65), and a *process condition* (anti-oscillation active, 0.50) that is orthogonal to v. As displayed, the equation is not a well-defined function of v; and the "—" branch (det/nd, "no protocol ceiling binds") is immediately contradicted by the same paragraph's reason-coded per-run ceilings, one of which (DIRECT_MEASUREMENT 0.75) *does* bind a DETERMINED verdict in the released corpus. The prose handles all of this correctly, but the paper's central formal object should be restated as c ≤ min over *applicable* caps (five-factor, state cap, subclass cap, process cap, per-run reason-coded caps). Also note the ≤50 cap appears twice in the code base under different names (diagnostician skill: `[PARAM_AMBIGUITY]`; orchestrator: anti-oscillation third-rediagnosis rule) — the paper names only the latter.

## 6. Verdict rationale

This is the rare submission where every number I recomputed matched the released artifacts, every disclosure I tested (bare-LLM dominance, calibration timing, weak stability pair, insufficient-runs gap, one-directional verdict typing, rubric circularity) turned out to be *more* precise than required, and the design flaws that remain (n=9, single execution, author-designed instruments, missing ablation arms) are enumerated by the author rather than discovered by me. The remaining defects are presentational: Eq. (1) does not type-check as written, and the keyword-calibration disclosure stops one sensitivity analysis short of airtight.
