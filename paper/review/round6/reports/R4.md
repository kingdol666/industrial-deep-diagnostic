## 2. Spot checks that FAILED (integrity findings)

**F1. Released-artifact index row `00_input/brief.json` does not exist (Table A2, p. 65).**
Checked 19 index rows across 5 run dirs (skab_valve1_1, tep_d04, tep_d11, indpensim_batch093,
skab_cavitation_13): 18 rows exist (`data.csv`, `ontology.json`, `validate_report.json`,
`data_analysis_conclusion.json`, `visual_analysis.json`, the diagnosis 4-piece, `judge_feedback.json`,
`optimizer_preflight.md`, `html_review.json`, `report.md`, `diagnostic-report.html`, `optimizer.md`,
`.pipeline_events.jsonl`, `pipeline_finalize_report.json`, `run_summary.json` — all present).
`00_input/brief.json` is **missing in all 5 run dirs**; the blind brief is actually released at
`results/benchmark/briefs/<case_id>.brief.json` (`run-tier.mjs:128` writes `BRIEFS_DIR`).
The artifact exists; the index path is wrong. For a paper whose core pitch is a checkable artifact
index, a dead path is a defect, though trivially fixable.

**F2. The universal RAG-degradation claim is contradicted by a released canonical artifact
(§3.2 p.8 "probe failures or empty retrievals, both recorded"; §9 "the RAG channel either failed
its health probe or returned empty retrievals in any benchmark run").**
Three runs do record exactly that: `indpensim_batch001_control` ("3s health probe failed"),
`indpensim_batch093` (health OK but retrieve attempts → 400/empty), `tep_d14` ("returned no
TEP-domain knowledge"). But the canonical `skab_valve1_1` run (202609150453290 — the case-study
scenario) records a **successful** retrieval: `00_input/rag_deep_understanding.json`
`retrieval_meta.engine: "rag-retrieval-engine @ localhost:8764"`, `chunks_retrieved: 21`,
`key_sources` including web hits (ResearchGate pump-fault paper, Texas A&M rotordynamics guide),
and **no** degradation/probe event in its `.pipeline_events.jsonl`. The downstream conclusion — no
L6 evidence enters any verdict — survives my check (zero occurrences of the web sources or any
"L6" citation in that run's `04_diagnostics/*.json`; the retrieved physics stayed in the
ontology-context layer). But the paper's stated *reason* is false for this run and must be
reworded (e.g., "in three runs the channel failed or returned empty retrievals, both recorded; in
one run retrieval succeeded but no external reference was cited in any surviving chain").

**F3. "The SKAB 'other'-group scenario removes the label entirely" (§9) is not literally true.**
The ground-truth word *cavitation* is embedded in the case identifier `skab_cavitation_13`, which
is (i) the first field of the agent-visible blind brief
(`results/benchmark/briefs/skab_cavitation_13.brief.json`: `"case_id": "skab_cavitation_13"`) and
(ii) the run-directory name passed to agents as `RUN_DIR`. The leakage sentinel
(`scripts/benchmark/check-leakage.mjs`, which I ran: RESULT PASS) scans `process_description`,
forbidden keys, glossary, and notes — but **not the `case_id` field**, so its PASS does not cover
this channel. The paper's §5 C1 sentence "no ground-truth string may appear in any agent-visible
brief" is, by the paper's own definition, violated for this scenario. Mitigation: the verdict is a
capped COMPETING_SET with `top1:false` in `metrics.json`, so **no headline accuracy number is
inflated**; but the blind-set-robustness narrative (§7.2, §9) rests on the label being hidden, and
a reader must be told the identifier embeds it (or the case must be re-aliased).

## 3. Honesty audit — strong overall

Disclosures verified real, specific, and correctly stated:
- The three COMPETING_SET misses are narrated as misses (§7.2, §9), including the one
  verdict-type compliance miss (SKAB valve) counted against the paper in Table 6/7.
- The single-LLM ablation beating the pipeline (9/9 vs 6/9) is stated in the abstract, §8.3, §9,
  and the conclusion — the paper actively argues against its own accuracy superiority.
- INSUFFICIENT-RUNS on the randomly drawn retest scenario is reported rather than substituted
  (§8.4); WEAK mechanism-level agreement on skab_valve1_1 is disclosed with the rule that produced
  it (`consistency_audit.json`: consistent 2 / weak 1 / divergent 0 — matches).
- IDV14 period-estimate instability across sessions (≈12 min vs ≈30 min) is disclosed and the
  canonical run identified (§8.4; `stability_report.json` confirms 82→89 conf, same type).
- Era discipline (v1→v2 flips of SKAB valve/cavitation/IDV3) is shown per-run in
  `stability_report.json` and narrated as a system revision, not hidden.
- Overclaiming scan: "guarantees"/"proves" do not occur for empirical claims; the abstract's
  "gated process guarantees" is defensible given the gates are enforced; §6.1 states ceiling
  compliance is "a property of the protocol's arithmetic, not an empirical discovery" — exemplary.
- The internal-integrity-audit disclosure (§5 C4) maps to a real released document
  (`docs/benchmark/AUDIT-2026-09-13.md`) which is *more* damning than the paper (it documents the
  earlier brief-level truth leakage); the current briefs verified clean for all 6 TEP faults and
  IndPenSim (grep for IDV/stiction/batch-93 tokens: clean), and current-era runs (20260914–15)
  postdate the audit — the "re-executed end to end" claim is supported.
- One wording nit: Table 6's judge mean 93.1 spans 12 scenarios including 3 controls; the caption
  says "post-threshold ≥90" but not n=12.
