## 1. Verdict summary

The figure set is well above the AEI average: all result figures are vector PDFs authored at final
print width (5.4 in, TrueType embedded), on an Okabe–Ito palette with a text cue in essentially
every colour-coded cell; captions are long and largely self-contained; and — the part I stress-tested
hardest — **every number I could read in every figure matches the corresponding number in the text,
the tables, and the released benchmark artifacts** (see §3; ~25 values checked, zero mismatches).
The defects found are presentation-level: one caption that names the wrong colour, an in-figure
annotation colliding with the data trace, a colour whose meaning flips between Fig 3 and Figs 6/8,
and a systematic 2–12 % font shrinkage because figures authored at 5.4 in are included at
0.88–0.98\textwidth. Nothing is unreadable or wrong in a way that changes a conclusion, but three
items must be fixed before this is print-clean.

**Verdict: MINOR_REVISION.**

## 2. Figure-by-figure findings

### Fig 1 — Skill execution architecture (TikZ, p12)
- Clear five-plane stack; arrows show the client→engine→orchestrator→pipeline→audit dataflow, so
  modules AND handoffs are both present. Text labels carry the semantics; colour is decorative
  only. Good.
- **Should-fix (legibility):** the `\tiny` engine-layer line ("pre-flight probing (unknown → 400 …
  ablation axis)", `main.tex:151`) measures ≈5 pt effective after `\resizebox{\textwidth}` — below
  any print-comfort threshold. Move that line to `\scriptsize` and let the box grow, or shorten it.
- Placement: first cited p9 (§3.1), figure lands p12 — 3 pages of drift inside one section. Not a
  violation (placeins holds it in Section 3), but AEI production will pull it closer; consider `[!t]`
  on a nearer page.

### Fig 2 — Diagnostic pipeline flow (TikZ, p14)
- Two-row serpentine, checkpoint tags, dashed amber repair loop with label "repair: best-of-3,
  global ≤ 5", deliverables row. Clean at print size, no overlaps, colour never sole carrier
  (CP-8 · ENDORSED / CP-9 · overall PASS are also written out).
- **Cosmetic (caption):** caption says the bottom row "reads right to left, returning to the setup
  stage" (`main.tex:256`). No edge returns to the setup stage — the serpentine merely returns
  leftward. Rephrase ("…reads right to left, mirroring the top row") to avoid implying a cycle
  that does not exist.

### Fig 3 — Benchmark outcomes (p33)
- (a) Stacked bars by dataset: SKAB 0/2 amber, TEP 5/6 blue+grey, IndPenSim 1/1 blue. Verified
  against `metrics.json` (`by_dataset`: skab top1 0/topk 2; tep top1 5; indpensim 1) — exact.
- (b) Rubric (filled) vs judge (open) dot plot: filled 85 (SKAB valve) and 90 (IDV11), all others
  100; open markers in 90–97. Matches `rubric.json` scores {skab_valve1_1: 85, tep_d11: 90, rest
  100} and the 12 `judge_score` values (mean 93.08, range 90–97). Shape (filled/open) + colour
  (blue/grey) + row labels give three redundant cues. Good.
- **MUST-FIX (cross-figure colour semantics):** in (a) amber = capped COMPETING_SET *with* the true
  mechanism ranked, grey = the single unranked miss (IDV3). In Figs 6 and 8 amber = capped
  COMPETING_SET *without* the true mechanism (IDV3 is the amber cell there), and Fig 4 uses amber
  for *all three* capped verdicts. The same hue therefore carries the opposite meaning in Fig 3(a)
  vs Fig 8 — a reader cross-referencing "the amber scenario" will misidentify the miss. Each
  caption defines its own legend, but three different amber semantics across four result figures is
  a genuine mislead. Fix: adopt the Fig 8 convention everywhere (sky = capped CS ranked; amber =
  capped CS unranked) and recolour Fig 3(a) and Fig 4 accordingly.

### Fig 4 — Reported confidence (p36)
- All 12 bars carry printed values (CS 0.65/0.58/0.60; DET 0.79/0.88/0.75/0.82/0.80/0.89; normal
  0.78/0.88/0.88) — each one matches `gradings/*.json` confidence and Table 7 exactly. The 0.70
  dashed ceiling and "overconfidence = DETERMINED and wrong: 0 occurrences" axis note are honest
  touches. Hatched control bars are distinguishable from filled fault bars without colour.
- **Should-fix:** green (IndPenSim DET) vs blue (TEP DET) is an unexplained distinction — the
  caption treats them as one class ("Blue and green bars are DETERMINED fault verdicts"). Either
  state "green = IndPenSim, blue = TEP" or use one hue. (Related to the amber clash above.)
- **Cosmetic:** included at 0.88\textwidth (`main.tex:491`), so the 7.2–7.3 pt value labels and y
  tick labels print at ≈6.4 pt — below the 7 pt the file's own header targets
  (`make_figures.py:24-26` explicitly warns about down-scaling). Include at `\textwidth`.

### Fig 5 — Case study, SKAB valve (p37)

  above the trace band, and keep it inside the axes.
- **Cosmetic:** the bottom evidence-chain strip is a 5-line, 7.4 pt paragraph embedded in the
  figure. Legible, but AEI style prefers that prose in the caption; at minimum keep it ≥8 pt.
- **Cosmetic:** in-figure gloss "bins 30/31 L/min" vs precise chain values 30.62/31.73 — the

### Fig 6 — TEP per-fault grid (p41)

### Fig 8 — Suite comparison matrix (p46)
- The best figure in the paper: every cell has text, the PCA columns print their numeric detection

## 4. Defect list

### Blocking (must fix before acceptance)
1. **p42, Fig 7 caption:** colour key calls the controls row blue; it is drawn green
   (`main.tex:529`). Caption–figure contradiction in the headline comparison figure. One-line fix.
2. **p33/p36/p41/p46, amber semantics clash:** Fig 3(a) amber = capped CS *ranked*; Figs 6/8 amber
   = capped CS *unranked*; Fig 4 amber = all capped CS. Same hue, opposite meanings across result
   figures — actively misleading when cross-read. Standardise on the Fig 8 convention.
3. **p37, Fig 5:** teal annotation overflows the axes and collides with the flow trace (spike
   through "1.18"; `make_figures.py:407-410`). Shorten/reposition inside the axes.

### Should-fix
4. **pp12/36/42/46, effective font sizes:** figures authored at 5.4 in are included at
   0.88–0.98\textwidth (`main.tex:444,491,521,528,574`), shrinking 7–7.3 pt labels to ≈6.4 pt —
   the exact failure mode `make_figures.py:24-26` says it was written to prevent. Include all
   matplotlib figures at `\textwidth` (or bump the small fontsizes); likewise Fig 1's `\tiny`
   engine line is ≈5 pt effective (`main.tex:151`).
5. **p46, Fig 8:** "no (correct: control)" overflows the last cell into the figure margin
   (`make_figures.py:343-346`).
6. **pp65–66:** Tables A1/A2 each strand a ~60 %-empty float page; tighten placement.
7. **p14, Fig 2 caption:** "…reads right to left, returning to the setup stage" implies a cycle
   that does not exist; rephrase (`main.tex:256`).
8. **pp9→12, p12→14:** Fig 1 and Fig 2 drift 3 and 2 pages from first citation; nudge placement.

### Cosmetic
9. p46: caption "--" vs figure "-"; integer vs one-decimal rounding vs Table 8.
10. p37: 5-line 7.4 pt evidence-chain paragraph inside the figure; "30/31" truncation of
    30.62/31.73.
11. p41 vs p65: Fig 6 and Table A1 duplicate content (declared companion — acceptable).
12. p15: ENDORSED hyphenated across lines in Table 2.
13. p42: 100 % marker touches the "3/3" label.

## 5. PUBLISH-READY assessment

Not yet. The quantitative backbone is exemplary — I could not break a single number in eight
figures and eleven tables against the released artifacts — but the Fig 7 caption error, the amber
semantics clash, and the Fig 5 annotation collision are exactly the kind of avoidable
visual-communication defects AEI copy-editing should not have to catch. All three are one-line-to
one-hour fixes; with them applied (plus the font-size pass), the figure program is
publication-grade.
