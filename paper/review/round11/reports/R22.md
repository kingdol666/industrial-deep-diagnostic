## 4. Findings

### MUST-FIX (blocking)
1. **§3.1, p.10 — the parenthetical "(all in the optional layers)" is checkably false for one
   of the six checklist-less packages.** The six are industrial-analysis-auto (the
   orchestrator's own package — the paper's own Fig 1 gives the orchestrator its own plane;
   not an optional layer), industrial-data-preprocessor (executed at Step 0.5 on the
   diagnostic path, orchestrator SKILL.md:232-252), rag-knowledge-builder,
   industrial-analysis-enhance-auto, diagnostic-html-visualizer, darwin-skill. Note the irony
   that the sentence opens with "Three scoping clarifications make this layer map onto the
   released software precisely". One-line fix, e.g.: "…while the six that do not are the
   orchestrator's own package, the Step-0.5 preprocessing utility, and four optional-layer or
   meta packages". All surrounding counts (12/18, 8/8, 6/18) are correct — only the
   attribution of the six is wrong.

### SHOULD-FIX (non-blocking)
1. §3.2 RAG sentence: the parenthetical "(the two other SKAB runs, cavitation and normal
   control, have no RAG artifact)" is accurate but incomplete as an exemplar of "remaining
   runs" — the canonical tep_d01/d03/d04/d07/d11 runs also lack RAG artifacts (their
   fallbacks are recorded as run events, per the preceding clause). Add "e.g." or "inter
   alia" so a reader who counts artifacts does not report a spurious mismatch.
2. p.17 is a mostly empty float page (Table 3 alone); consider repacking so Table 3 shares a
   page with §3.4 text or Table 2.
3. §3.1 "18 skill packages executed by 14 specialised agents": several of the 18 packages
   (darwin-skill, rag-knowledge-builder, diagnostic-html-visualizer, industrial-data-preprocessor)
   map to no agent of the 14; a half-sentence acknowledging the loose many-to-one mapping
   would preempt a pedantic recount.
4. §3.3 "Step 3.5" vs the orchestrator's "3.3" label: the paper already flags this dual naming
   explicitly (good), but a footnote pointing out that the pipeline-level name is 3.5 while
   the dispatch label is 3+3.3 would help tool-builders parsing the event logs.

## 5. Verdict rationale

Every architecture mechanism I checked — engine count and ids, error codes, contract
functions, dispatch table, nested VLM call, all nine checkpoint predicates, module-contract
filenames, all 14 graded artifacts, repair counters and scope mechanics, anti-oscillation
cap, RAG per-run variance (21 chunks / rag_available=false / fallback events / single
corroboration-only L5/L6 item), model assignment, ports, WAL — is true of the released
codebase, most of it verified to the exact line. The single defect found in my focus area is
a one-clause mis-attribution inside the very sentence that promises precise mapping, plus a
float-page blemish. That warrants a mandatory one-line correction, not a re-review cycle.
