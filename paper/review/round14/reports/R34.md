## 1. Overall assessment

Section 2–3 (System Architecture, rendered pp. 9–18) is an unusually faithful systems description. Every quantitative and structural claim I could check against the repository checks out — the package census (18/14/8/12+6), the engine-layer realization (12-entry capability table + 2 first-party wiring entries, typed 400/409), the checkpoint table CP-1..CP-9 (predicates and failure actions verbatim against the orchestrator skill), the repair governance (best-of-3, global cap 5 via `repair_spawn`, anti-oscillation ≤ 0.50), the VLM nested dispatch inside data-processor Phase 5.5 with the orchestrator's `3+3.3` dispatch-table label, the model assignment (only the VLM agent on `vision`), and — most impressively — the per-run RAG engagement narrative, which I verified event by event against the *canonical* run directories (the run dirs named in the grading JSONs, e.g. canonical `tep_d01` = `202609150454126…`, not the superseded 09-14/09-12 directories). This is the rare architecture section that survives adversarial checking against its own codebase.

The defects found are presentation-level, concentrated on Table 2: the table overflows its float page by 15.19 pt (a hard LaTeX warning; the folio is visibly displaced), and its caption mischaracterizes two rows as "sub-agent's contracted deliverables" when one row is authored by the main agent and one by a deterministic script.

**Verdict: MINOR_REVISION.**

## 4. Judgment

Content: §2–§3 is publishable-quality systems writing — precise, scoped ("Three scoping clarifications…"), and honest about optional layers and the not-yet-exercised engine-substitution axis. It is verifiable to an unusual degree; every one of my eight substantive architecture spot checks matched the codebase and the canonical graded runs, including the RAG paragraph that is essentially a per-run audit narrative.

Presentation: two blocking-for-camera-ready defects, both on Table 2 (float overflow 15.19 pt with displaced folio; caption's "sub-agent's" inaccuracy), plus float-packing/cosmetic polish. Neither touches the science; both are cheap, deterministic fixes.

**Verdict: MINOR_REVISION.**

MUST-FIX:
1. p.17 / Table 2 (tab:modules) — float overflows its page by 15.19 pt (`main.log:1008`, input line 197), folio displaced below the type area; repack as done for Table 4 (`main.tex:477-480`).
2. p.17 / Table 2 caption — "The table lists each sub-agent's contracted deliverables" is false for the main-agent (row 1) and deterministic-script (row 11) rows; reword to "each stage's contracted deliverables".

SHOULD-FIX:
1. pp.16/18 — §3.5 text page ends ~40% short and Table 3 strands alone on p.18; consider a float-page consolidation.
2. Table 2 HTML-build row — detached `→` glyphs at the Produces column edge read as stray marks; set arrows inline.
3. §3.1 — eight distinct sub-agents produce nine dispatch rows (report-reviewer runs at 5b and 7); one clause would preempt miscounting.
4. Disclose the agent→model assignment (8 default, 3 sonnet, 1 vision) in §5.4 or an appendix line; "only VLM on vision" is currently checkable but unstated.
5. Canonical tep_d01's `run_config.json` carries no RAG probe key while the orchestrator skill instructs recording it there (`SKILL.md:225`); the paper's event-based phrasing is correct, but the skill text and runs disagree — align before release.

PUBLISH-READY: no — the architecture content is verified faithful to the codebase and canonical runs, but Table 2's float overflow and caption inaccuracy must be fixed before this is camera-ready.
