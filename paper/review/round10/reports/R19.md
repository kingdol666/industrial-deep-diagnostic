## 2. Blocking defects

**F1. Fig 8 caption mis-names column 1's resolved-DETERMINED colour (p50).** Caption: "Column 1: ... **green** resolved DETERMINED (Top-1), sky capped ..., amber capped ..., green 'normal' for controls." The rendered figure draws all seven Top-1 cells (incl. IndPenSim batch-93, 0.88) in IDD dark blue, and the in-figure legend patch "IDD resolved (Top-1)" is dark blue; green in column 1 is used only for the three "normal" controls. The caption thus (i) names the wrong hue for the primary column and (ii) uses "green" for two different column-1 meanings (Top-1 and normal), which the drawing does not do. Fix: change "green resolved DETERMINED (Top-1)" to "dark blue resolved DETERMINED (Top-1)". Blocking: the caption is the declared colour key for the paper's central comparison figure. (Source: `make_figures.py` `fig_suite_matrix` — `col, txt = BLUE, "Top-1..."`.)

**F2. Fig 6 caption names no colours and the figure has no legend (p44).** The matrix draws six colours — green (FE correct), vermillion (GPT-4o "wrong" on IDV1), pale grey ("unscored" IDV3/4 and "yes"), darker grey (PCA "no"), IDD dark blue ("Top-1 (conf.)"), amber ("capped CS (0.60)") — none of which is named in the caption ("Per-fault comparison on the TEP subset: IDD vs. FaultExplainer ... "). This was supposed to be fixed by the recent caption update; it was not. A grayscale print or a colour-blind reader has no key for the correct/wrong/unscored cells. Fix (one sentence): "Green cells: FE correct; vermillion: FE wrong; grey: unscored by FE's PCA implementation or not PCA-detectable; dark blue: IDD Top-1 correct; amber: IDD capped COMPETING_SET." Blocking under this round's rule that every drawn colour be named in caption or legend.

**F3. Fig 4 uses green for the IndPenSim DETERMINED bar without declaring the dataset coding — and contradicts Fig 8 (p38 vs p50).** `fig_calibration` colours the batch-93 DETERMINED bar GREEN (`base = GREEN if dataset == "indpensim"`) while the caption only says "Solid blue/green bars are DETERMINED fault verdicts", i.e. green is named but never explained; the reader's working convention elsewhere (Figs 7, 8) is green = control/baseline hit, so a lone green bar in a fault bar-chart invites the misreading "is this a control?". The same scenario-verdict (batch-93, 0.88, Top-1) is drawn dark blue in Fig 8 column 1 — two different colours for the identical datum across two figures, neither explained. Fix (preferred): recolour the batch-93 bar IDD dark blue in `make_figures.py::fig_calibration` and drop "green" from the caption; minimal alternative: append "(the green bar is the IndPenSim batch; dataset coding)" to the caption. Blocking as an undeclared colour semantics + cross-figure contradiction.
