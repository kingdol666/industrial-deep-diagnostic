## 1. Verification of the §2.1 scoped claims (the three "scoping clarifications")

### Claim A — 18 packages / 14 agents / 8 dispatched + nested VLM
- `.claude/skills/` contains exactly 18 skill package directories; `.omp/agents/` contains
  exactly 14 agent definitions. The 8 dispatched specialists named in the paper
  (context-builder, data-processor, diagnostician, judge, report-reviewer, reporter,

  `.claude/skills/industrial-data-processor/SKILL.md:78` ("VLM visual analysis is dispatched via
  a separate Agent() call to the vlm-visual-analyzer Agent") and `:83` (section heading "VLM
  Visual Analysis Dispatch (Phase 5.5)"). MATCH.
- The `3+3.3` alias: the orchestrator's dispatch table labels the data-processor step
  `3+3.3 ... (includes VLM visual analysis)` (SKILL.md:57, :82, :109, :315). MATCH **as to
  content**, but the paper says "the orchestrator's own **log** labels this sub-step 3+3.3"
  (main.tex:171). The event log of the canonical run
  (`workspace/diagnostic-runs/202609150453290_bench_skab_valve1_1/.pipeline_events.jsonl`)

  `visual_analysis`, `vlm` once). The label lives in the orchestrator skill document (dispatch
  table), not the log. **MISMATCH (wording)** — should read "the orchestrator's dispatch table /
  skill manifest labels this sub-step 3+3.3".

### Claim B — "all eight dispatched packages carry the checklist; five of the eighteen do not"
- All eight dispatched packages DO carry `references/agent-protocol.md` (verified per directory).
  MATCH.
- Packages WITHOUT `references/agent-protocol.md`: **six**, not five — `darwin-skill`,
  `diagnostic-html-visualizer`, `industrial-analysis-auto` (the orchestrator's own package),
  `industrial-analysis-enhance-auto`, `industrial-data-preprocessor`, `rag-knowledge-builder`.
  Five of these are optional-layer packages; the sixth is the orchestrator package itself. The
  sentence "all eight dispatched packages carry the checklist, while five of the eighteen
  packages (the optional layers) do not" (main.tex:130) leaves the reader computing 8+5=13≠18
  and asserts a false count ("five of the eighteen"). **MISMATCH (count)** — fix to e.g. "six of
  the eighteen (the five optional-layer packages and the orchestrator's own) do not".
- Note: the alternative protocol files that exist in two of these packages
  (`orchestration-protocol.md` in enhance-auto; `html-builder-protocol.md` etc. in
  diagnostic-html-visualizer) do not change the count, since the paper names
  `references/agent-protocol.md` specifically.

Schemas for its artifacts, and validation scripts that machine-check those artifacts"

  - industrial-judge: protocol YES, schemas 1, scripts 1

## 6. Overall judgement

§2–§3 is, with three sentence-level exceptions, faithful to the released system to an unusual
degree: module filenames, checkpoint predicates, engine ids/contract/error codes, repair
counters, ceiling split (agent-documented vs machine-enforced), evidence ladder, RAG per-run
degradation, and the nested-VLM structure all verify against the tree. The exceptions are
confined to the paragraph whose explicit purpose is scoping precision (main.tex:130 and :171):
(a) "five of the eighteen packages do not carry the checklist" (actually six, one of which is
the orchestrator's own package); (b) "each dispatched sub-agent package is a directory of
protocol + JSON Schemas + validation scripts" (false for physical-auditor and html-visualizer,
half-false for ontology-builder and html-reviewer); (c) "the orchestrator's own log labels this
sub-step 3+3.3" (the label is in the skill's dispatch table, not the event log). Because the
paper's credibility rests precisely on claim-to-code fidelity, these should be fixed, but they
are one-sentence edits with no knock-on effect on any result — a minor revision.
