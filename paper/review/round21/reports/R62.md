## 3. Weaknesses

- **W1 (precision, §5 p.28):** the "eight dedicated fields / three notes" sub-split of the
  eleven marked logs. A strict field-key count yields 9/2: tep_d00's marker is the dedicated
  field `harness:"inline-degraded"` (×7 events) and tep_d03 carries
  `harness_mode:"inline_non_agent_harness"` alongside its disclosure. The headline 11-of-12,
  the named exception skab_cavitation_13, and every quoted string are exact. One-line fix.
- **W2 (presentation, Table 4 p.26):** commit 221d061's message is "reproduce the comparator
  baselines for real (baseline-lab)" and the commit bundles a large baseline-lab tree; the
  keyword calibration rides in the same commit's `benchmark_cases.json` diff (with an explicit
  `keyword_revision` annotation). The paper's claim is factually correct (the calibrated set
  IS pinned there, date matches 11:20Z) but a reader auditing via the commit message alone
  could be misled; a half-sentence noting the co-committed baseline-lab work would pre-empt it.
- **W3 (minor, §3.1 p.10):** "most also ship the JSON Schemas and validation scripts" is
  accurate but unverifiable at the stated granularity without enumerating each package's
  scripts/schemas dirs; the checkable part (protocol census) is exact. No action required.

No architecture claim in my scope was found false, inflated, or unverifiable; the §5
disclosure goes out of its way to be checkable and survives checking.
