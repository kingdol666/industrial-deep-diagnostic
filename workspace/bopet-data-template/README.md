# BOPET 产线数据分析数据模板包

> **一份可以直接发给产线的"数据交接模板"**：规定数据怎么导出、映射说明怎么写、随数据要附哪些说明，
> 并自带一套**符合系统要求、可直接跑通的样例数据**（BOPET 双向拉伸聚酯薄膜产线，12 μm 光膜）。
>
> 产线按本包格式导出真实数据 → 分析系统即可直接读取、诊断、出报告。

## 二、三件事，各看一份就够

**⓪ 完全没接触过这套系统的人：先读 [`00_零基础操作手册.md`](00_零基础操作手册.md)**
——它用大白话讲清了"系统为什么这么要数据、数据怎么导、文档怎么写、界面怎么点、报告怎么读"，
并附了可打印的核对清单与名词小词典；看完再回来按下面三条执行即可。

**① 产线：把数据导出来（看 `01_数据导出规范.md`）**

- 表头用你们自己的**设备节点代号**（如 `L3-TDO-N-ST-Z4-TE01`），**必须**附一份《参数代号对照说明》/映射表；
- 时间列 `时间`（`YYYY-MM-DD HH:MM:SS`）、数值不带单位、缺失留空、一行一个时间点；
- 同时写三份文字说明放进同一个文件夹（背景 / 异常与已做排查 / 代号对照，`02_data/` 里有现成范例）。

**② 产线：按格式填写映射与说明（看 `03_映射文档/映射文档编写指南.md`，填空直接用 `06_说明文档模板/`）**

- 只需维护 `tag_mapping.csv`（Excel 打开即可），字段含：代号、名称、单位、工段、设备节点、回路号、
  角色、目标值、正常范围、**物理含义**、相关物理规律；
- 系统最看重"物理含义"这一栏：它把统计现象翻译成物理机制的依据；
- 三份说明文档（工艺背景 / 异常与排查 / 代号对照）可以直接拿 `06_说明文档模板/` 里的模板填空，
  填好的文件复制进数据文件夹即可（样例成品见 `02_data/`）。

**③ 分析操作员：拿到数据后跑诊断（看 `04_运行说明/场景运行说明.md`）**

- 推荐路径：把数据文件夹复制到本仓库 `data/<线体_产品_窗口>/` → Web 控制台（<http://localhost:5180>）
  → 数据页选中该文件夹 → 诊断页选引擎与 `deep-diagnosis` → 启动；
- 拿到新数据先花 1 分钟做**数据体检**（`inspect.mjs` + `data_preprocessor.py`），避免格式问题白跑一次完整管线。

## 三、样例数据（`02_data/`）说明

| 文件 | 内容 | 规模 |
|---|---|---|
| `L3_line_main_10min.csv` | 主表：DCS 工艺参数 + 在线质量，表头全部为产线内部代号（54 列） | 3024 行（10 分钟 × 21 天） |
| `L3_lab_quality_2h.csv` | 化验表：雾度/晶点/热收缩率/拉伸强度/含水率（8 项指标 + 时间列） | 252 行（2 小时 × 21 天，时间点与主表对齐 → 自动合并） |
| `L3_GA_TH_PROFILE_10min.csv` | 膜厚横向剖面（独立文件）：时间 × 63 个横向测点（距北侧边 50~6250 mm，间距 100 mm），一行 = 一次全幅扫描 | 3024 行（10 分钟 × 21 天，扫描完成时刻比主表晚 5 分钟） |
| `工艺背景与设备说明.md` | 产线/设备/控制回路/内控标准/数据口径 | 范例 |
| `异常现象与已做排查.md` | 现象、时间线、已排查项、要向系统问的问题 | 范例 |
| `参数代号对照说明.md` | 命名规则 + 每个代号的名称/单位/物理含义 | 范例 |

数据特征（**故意做成真实难点**，用于检验系统是否真的会分析）：

- 平均厚度全程正常，问题只出现在**分布**（横向不匀率、边缘偏差）与**热收缩率**；
- 存在一个**缓慢劣化型**的注入故障（隐藏主因），与另外 3 个**时间上高度接近的干扰项**（原料/回料变更、
  环境降温、过滤器压差锯齿 + 两次计划换网）交织；
- 关键判别证据在"**南北两侧对比**"与"**闭环输出 vs 设定值**"上，而不是任何一个单点数值。
- 注入事件与生成参数详见 `05_生成脚本/generation_manifest.json`（内部核对用），
  以及 `04_运行说明/场景运行说明.md` 第 4 节的"期望结论方向"。

> ⚠️ **给分析 Agent 跑样例时**：不要把 `generation_manifest.json` 与运行说明第 4 节的内容喂给它，否则等于泄题。

## 四、把样例换成真实数据（产线视角）

1. 按 `01_数据导出规范.md` 导出，文件名与列代号称按你们自己的命名（**不需要和样例一致**）；
2. 用你们的代号重写 `03_映射文档/tag_mapping.csv`（新增/删除行即可），并同步一份 json（字段结构照抄）；
3. 重写三份说明文档（`02_data/` 下的文件名可自定，`.md`/`.txt` 均可，**不要写成大表格**）；
4. 自检：按 `04_运行说明/场景运行说明.md` 第 3 节跑一遍体检命令，确认"主表选择正确、说明文档进了 context、没有表被意外排除"；
5. 交给分析操作员运行。

## 五、常见疑问

- **表头是内部代号，系统看不懂怎么办？** —— 这正是映射文档存在的意义；映射表 + 对照说明 + 预构建本体三件套
  足以让系统理解每个代号。缺映射的列系统会标注"含义未知，仅作统计参考"，置信度会下降。
- **我们只有 Excel，可以吗？** —— 可以（`.xlsx/.xlsm/.xls`，多 sheet 会挑数据量最大的那个）；
  但更推荐 CSV：更少格式陷阱（合并单元格、公式、日期序列号）。
- **化验数据是 4 小时一次，能分析吗？** —— 能，但要满足 **行数 ≥100**（如 21 天 × 4 小时 = 126 行），
  且时间点落在主表时间轴上；不足 100 行请拉长窗口或改写进说明文档（详见导出规范第三节）。
- **要不要人工先把多张表拼成一张？** —— 不需要。系统会自动挑主表并按时间轴合并同轴的表；
  人工重采样/前向填充反而会引入假信号。若你们已有"对齐后的宽表"，直接给宽表也可以（系统会优先使用它）。
