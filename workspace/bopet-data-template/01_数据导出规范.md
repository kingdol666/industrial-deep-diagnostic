# 数据导出规范（发给产线，照此执行）

> **目的**：让产线按统一格式导出数据 + 撰写说明，使"工业深度诊断系统"能直接读取并给出可靠结论。
> **一句话要求**：**时间是第一列**（格式 `YYYY-MM-DD HH:MM:SS`），**表头用产线内部代号**（必须附映射说明），
> **缺失值留空**，**数值不带单位**，**一行一个时间点**，**最重要的表放在文件夹顶层**。

---

## 一、支持的文件类型

| 类型 | 扩展名 | 说明 |
|---|---|---|
| 逗号分隔文本 | `.csv` | **首选格式**，DCS/历史站导出直接用这个 |
| 制表符/分号分隔 | `.tsv` `.txt` `.dat` | 可自动识别分隔符 |
| Excel 工作簿 | `.xlsx` `.xlsm` `.xls` | 支持多 sheet：系统会挑数据量最大的 sheet；**建议 sheet 名与文件名一致** |
| JSON 记录数组 | `.json` | `[{"时间": "...", "代号": 值}, ...]` 形式 |
| Parquet | `.parquet` | 大数据集可选 |
| 文字说明 | `.md` `.txt` | 工艺背景、异常描述、代号对照（见第五节），会被系统当作"背景知识"读取 |

**编码**：UTF-8（**带 BOM 最稳**）或 GBK/GB18030（自动识别）。不要用 UTF-16。
**分隔符**：逗号优先；如导出为分号/制表符也可以，系统自动判断。
**单文件上限**：500 MB。超过 10 万行时系统会对统计做抽样（建议按分析窗口裁剪到 ≤10 万行）。

## 二、表结构的硬性要求（逐条核对）

1. **第 1 行必须是表头**，单层、单行；不要多级表头、不要合并单元格、不要标题行/单位行/空行；
   不要隐藏行列、不要保留公式（导出"值"）。
2. **必须有时间列**，建议命名为 `时间`（也可 `时间戳`/`Timestamp`/`DateTime`/`date`/`ts`）；
   格式 `YYYY-MM-DD HH:MM:SS`（如 `2026-09-20 08:30:00`）。
   - 不要用 Excel 日期序列号（如 46250.354）
   - 不要只给日期不给时间；不要拆分成年/月/日多列
   - 时区统一为本地时间（+08:00），不要混 UTC
3. **一行 = 一个时间点**；同一文件内时间不重复、整体递增。同一时刻多次采样请先按 1:1 汇总（均值/首次/末次，注明口径）。
4. **数值列不带单位、不带千分位、不带 `%` 号**：写 `240.35` 而不是 `240.35℃`、`1,234.5`、`98.6%`。
   单位统一写在表头（映射表里）或对照说明中。
5. **缺失值留空单元格**；不要用 `-999`、`NA`、`NULL`、`0` 等值代替缺失（会被当成真实测量值参与计算）。
6. **表头（代号）必须与映射文档逐字一致**（大小写、连字符都要一致）。代号一旦变更，必须同步更新映射文档。
7. 建议文件名：`<线体>_<内容>_<采样间隔>.<ext>`，例如 `L3_line_main_10min.csv`、`L3_lab_quality_2h.csv`。
   文件名不要用空格、斜杠、特殊符号（中文可以）。

## 三、给多少数据、怎样的数据能被真正分析（重要）

系统读取"一个文件夹"时的工作方式（已实测确认）：

- 选择**数据量最大且有时间列的表作为"分析主表"**；
- 文件夹顶层其它表：**≥100 行且与主表时间轴重叠**时，会**自动按时间合并**进主表；
- **少于 100 行的表不会进入分析主表**（只在预处理审计报告里记录一条排除原因）；
- 子文件夹内的文件**不会被自动扫描**（只扫描你指定的这个文件夹的顶层）；
- 多采样率数据**不要人工重采样或前向填充**，原样导出即可，合并与对齐由系统负责。

**所以请这样准备数据：**

- 数据窗口：**≥ 7 天（推荐 14–21 天）**，必须包含异常**发生前**的正常段（用于建立基线）；
- 主表：采样间隔 1–10 分钟，行数建议 ≥ 1000 行；
- 化验/抽检类低频数据（雾度、强度、含水率等）：
  - 若与主表时间轴对齐且 **行数 ≥100**（例如 21 天 × 4 小时 = 126 行）→ 会自动并入主表；
    并入后**非抽检时刻的化验列为空**（属预期行为，系统按可用点做统计与时滞分析），不要为了"填满"而做前向填充；
  - 若行数不足 100 → **不会被自动读取**，请把结论写进《异常现象与已做排查.md》，或把窗口拉长到累计 ≥100 行；
- 事件类（换网、清洗、停机、配方变更）：行数通常很少，请**同时**用两种方式给：
  (a) 作为 CSV 附在文件夹里（供查阅/校验），(b) 用一段文字写进《异常现象与已做排查.md》（系统一定能读到）。

## 四、测点（列）选择建议

**必须有**：

- 质量指标：厚度（均值/分布/边缘）、优品率、关键化验项；
- 工艺主线参数：挤出温度/压力、铸片辊温、纵拉温度、横拉各区南北两侧风温、线速/张力；
- 批次号、产品规格代号、产线运行状态（运行/降速/停机）。

**强烈建议有**（能大幅提高结论可靠性）：

- **控制回路的设定值（SV）与实际值（PV）成对给出**：这是区分"操作改了参数"与"设备能力变了"的关键；
- **闭环输出百分比（加热/阀门输出 OP）**：输出持续上升是执行器衰减的直接证据；
- 环境参数（车间温湿度、循环水温）：用于排除"季节/环境"这类混杂因素；
- 同类设备的**分侧/分区**测点（如横拉机南北两侧）：用于识别"单侧异常"这类关键证据。

**没有的测点不要用相近量代替**（例如用设定值代替实际值）；宁缺勿假。

## 五、必须随数据提供的三份说明（文字内容）

放在**同一个数据文件夹**里（`.md` 或 `.txt` 均可）：

1. **《工艺背景与设备说明》**：产线/产品、工艺流程、设备节点、控制回路、质量内控标准、采样口径、已知物理常识；
2. **《异常现象与已做排查》**：现象（什么时候、什么指标、什么形态：突变/缓变/周期）、发现经过、
   时间线上的相关事件（换网/清洗/配方变更/天气）、**已经排查过什么且结论如何**、希望系统回答什么问题；
   ⚠️ **不要写你猜测的根本原因**（会干扰系统独立判断）；如果有初步倾向，单独标注"未证实"。
3. **《参数代号对照说明》**：代号命名规则 + 每个代号的名称/单位/所在设备/物理含义
   （可用 `03_映射文档/tag_mapping.json` / `tag_mapping.csv` 的结构填写，两者内容一致即可）。

> 说明文件请用**段落与列表**书写；**不要把大段说明写成超过 5 行的 Markdown 表格**——
> 系统会把这类表格当作"数据表"处理，说明文字就进不了背景知识。

## 六、常见错误与系统表现（对照表）

| 错误做法 | 系统的表现 |
|---|---|
| 时间列缺失 / 无法解析 | 该表无法作为时序主表使用；图表只能用序号轴（不具时间意义） |
| 用了多级表头或标题行 | 列名变成"未命名/乱码"，映射失效 |
| 数值带单位或 `%` | 该列被识别为文本，无法参与统计与相关分析 |
| 缺失填 `-999` | 被当成真实测量（出现不可能的极值，污染结论） |
| 低频表不足 100 行 | 不进分析主表（只留审计记录），化验信息丢失 |
| 说明文档用了大表格（≥5 行） | 说明文字被当作数据表 → 很可能被排除，无法作为背景知识 |
| 只给平均值不给分布（边缘/极差/CV） | 无法发现"均值正常但分布劣化"类问题（本样例正是此类） |
| 只给实际值不给设定值/输出 | 无法区分"参数被改过"与"设备能力下降" |

## 七、导出前自检清单

- [ ] 时间列在第一列（或至少命名为 `时间`），格式统一、可排序、无重复
- [ ] 表头单行、无合并单元格、无公式
- [ ] 数值列纯数字，无单位、无千分位、无百分号
- [ ] 缺失值留空
- [ ] 数据窗口包含异常前后（**有正常基线段**）
- [ ] 主表 ≥1000 行；低频表 ≥100 行且时间点落在主表时间轴上
- [ ] 代号与映射表一致；新增/变更代号已更新映射文档
- [ ] 三份说明文件（背景 / 异常与排查 / 代号对照）已放在同一文件夹
- [ ] 文件夹里没有"答案/结论"类文件（如内部分析报告），避免干扰系统独立判断
- [ ] 抽样打开首行/末行/中间行各 3 条，人工核对数值与单位

## 八、交付方式

- 把**整个数据文件夹**打包（zip/rar）或以共享盘方式提交，保持文件夹结构不变；
- 文件夹名建议：`<线体>_<产品>_<窗口>`，例如 `L3_GP12_20260920-20261010`（不要用空格、`/`、`\`）；
- 同时提交映射文档与三份说明（就在数据文件夹内或随包附带）。

## 九、多源异构数据（剖面 / 2D 场 / 图像序列 / 时序文字备注）怎么给

除"一行一个时间点"的标量表（第二节规矩）外，产线上常见的四类**非标量**数据——
横向扫描**剖面**（如膜厚 时间×位置）、**二维场/点位图**（温度场、浓度场）、
**图像序列**（WAXS 衍射、CCD 检查、热成像）、**带时间的文字备注**（操作/交接班/化验备注）——
同样可以交给系统。系统有专门的异构前处理阶段接收它们，给法如下；
**第二节的红线（时间格式、缺失留空、永不插值）对它们全部继续有效。**

### 9.1 剖面数据（时间 × 位置，如膜厚横向扫描）

- 两种给法任选其一：
  - **宽表**：`时间,pos_01,pos_02,…,pos_N`——一行 = 一次扫描快照，一列 = 一个位置点位；
  - **长表**：`时间,位置,值`——一行 = 一个"时刻 × 位置"组合，系统自己转成快照矩阵。
- 位置列建议按 `pos_01…pos_N` 顺位命名（`pN`、`chN`、`通道N`、`测点N`、`点位N` 这类规律命名也能识别）；
  位置列号与实际物理位置（边部/四分之一处/中部）的对应关系，请写进《参数代号对照说明》。
- 扫不到的位置**留空**。某次快照的有效位点不足 **60%** 时，系统对该快照**只做幅值统计**
  （均值/极差/分位数），形状类特征（斜率、边缘偏差、最差点位等）自动置空，并在报告里**如实注明降级**——
  不要为了"凑满"去填数，填出来的形状特征是假的。
- 剖面文件里的数值列应当是**同一个物理量沿位置的扫描**（幅值同量级）。
  互不相干的工艺参数不要混进剖面文件，放主表里去。

### 9.2 二维场 / 点位图（温度场、浓度场、点位 map）

- 用**长表**：`时间,x,y,值`，一行 = 一个"时刻 × 坐标"点；x/y 用现场统一的坐标或行列号，含义写进映射说明。
- **规则网格**（栅格覆盖率 ≥60%）才做完整空间特征：热点/冷区面积、质心、梯度、左右不对称等；
- **随机散点**（测点稀稀拉拉、不成网格）当前版本**只登记不分析**（保留原始记录，后续版本支持）——
  请如实知道这一点，不要指望散点出云图；
- 缺失格子**留空**，系统**永不插值**补网格。

### 9.3 图像序列（WAXS/SAXS 衍射、CCD 检查图、热成像）

- 给法（二选一，推荐都给）：
  - **图片文件 + 索引 CSV**：图片集中放一个文件夹（如 `imgs/`），数据文件夹里放一张两列的
    索引表 `时间,文件名`（图片在子文件夹时写相对路径，如 `imgs/waxs_001.png`）；
  - **文件名内嵌时间戳**：`…_YYYYMMDD_HHMMSS.扩展名`，如 `waxs_20261015_083000.png`。
- **有仪器标定请务必一并给**：衍射仪标定文件（如 `detector.json`：像素尺寸、束心、探测器距离、波长）。
  - 有标定：才可能做 q 空间**绝对**指标（峰位、晶面间距等物理量）；
  - 没有标定：只能做**整图统计**（亮度均值/熵/暗区占比/清晰度等）与探测器坐标系内的**相对**分析
    （帧间差、径向分布的相对变化）——系统做不了 q 空间绝对指标，也不会假装能算；
- 图像保持仪器原始输出，**不要**旋转、裁剪、压缩、批量改名后再给。

### 9.4 时序文字备注（操作备注、交接班记录、化验备注）

- 两种给法：**`时间,备注` 两列 CSV**（推荐，一行一条），或**每条前带时间戳的 .md/.txt**；
- **日期必须写清格式**：推荐 `2026-10-15 08:30:00`。像 `05/07/2026` 这种"05 是月还是日"有歧义的日期，
  系统**整份源跳过**（宁可不读也不猜），你的备注会全部落空；
- 备注写**事实**（几点、做了什么、看到什么），不写结论性猜测（同第五节规矩）。

### 9.5 通用红线（重申，对以上全部形态有效）

- 时间一律 `YYYY-MM-DD HH:MM:SS`（时间列或索引表第一列）；
- **缺失留空**；系统**永不插值、永不前向填充**——宁可如实标"缺"，绝不造数；
- 采样稀疏的源（快照间隔远大于主表）不会硬挤进统计主列，而是以**"稀疏辅助"身份**进入分析：
  走特征表、热图、视觉证据这条路，并在报告里如实标注"稀疏"。

### 9.6 系统会拿它们做什么（一句话版）

- 每类源被投影成**锚定在同一时间轴上的特征列**（列名以 `HX-` 开头），与主表按时间对齐，一起进统计与诊断；
- 每个特征列**可溯源**：来源文件（以 sha256 指纹核对）、计算公式、证据等级都记录在随 run 交付的契约文件里；
- 剖面会出**"时间 × 位置"热图**——一眼看出"从哪天开始、从哪个位置开始"不对，这是单点趋势图看不到的。
