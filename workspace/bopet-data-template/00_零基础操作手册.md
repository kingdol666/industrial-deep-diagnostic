# 零基础操作手册：从产线数据到诊断报告

> **这份文档写给不会写代码、没接触过人工智能的产线/品质/工艺同事。**
> 看完你就能独立完成三件事：**① 把数据导对 ② 把说明文档写对 ③ 让系统跑出诊断报告**。
> 全程只需要会：导出 Excel/CSV、打字、点鼠标。
>
> 配套文件：`01_数据导出规范.md`（对照检查用）、`03_映射文档/映射文档编写指南.md`（填代号用）、
> `04_运行说明/场景运行说明.md`（进阶操作）、`06_说明文档模板/`（可直接填空的三份模板）。

---

## 0. 先花 3 分钟理解：这个系统到底要什么

### 0.1 一个比喻

把"工业深度诊断系统"想象成**一位刚入职的高水平分析专家**：

- 他很聪明，会统计、会做因果推断、会写报告；
- 但他**不在你们厂里**，不认识你们的设备，也没参加过上周的生产例会；
- 你给他的东西就是他的全部信息来源。**他只能看到你给的那张表和你写的那几页纸。**

所以：**你给他什么，他就能分析什么；你没给的，他分析不了，也不会瞎猜（他会明说"证据不足"）。**

### 0.2 他有三个"天生看不见"，你必须补上

| 他看不见什么 | 你必须给什么 | 不给会怎样 |
|---|---|---|
| **看不见代号的含义**。`L3-TDO-N-ST-Z4-TE01` 对他就是一串字母 | **映射文档**（代号 → 中文名/单位/设备/物理含义） | 他只能说"某一列在下降"，无法说出"横拉机北侧4区风温在下降"，结论必然模棱两可 |
| **看不见现场背景与现象**。不知道你们什么产品、什么流程、什么时候发现的问题、车间查过什么 | **三份说明文档** | 他只能闷头算数，无法提出和排除"候选原因"，报告没有说服力 |
| **看不见时间语义**。不知道哪一列是时间、每一行代表几分钟 | **规范的时间列**（第一列 `时间`，格式 `2026-09-20 08:30:00`） | 所有"先后关系/滞后效应"都算不出来——而工业诊断的核心就是"谁先变、谁后变" |

### 0.3 三条铁律（记不住别的，记住这三条也能跑起来）

1. **第一列是时间**，格式 `YYYY-MM-DD HH:MM:SS`（如 `2026-09-20 08:30:00`）；
2. **表头用你们自己的代号没问题**，但**必须附一份代号对照表**（每个代号：是什么、什么单位、装在哪台设备上、代表什么物理量）；
3. **缺失值留空**，数值**不要带单位**（不要 `240.35℃`、不要 `98.6%`、不要 `1,234.5`）。

## 1. 数据导出要求（手把手）

### 1.1 第一步：先决定"分析哪一段时间"

- **窗口长度：至少 7 天，推荐 14–21 天**（少于 3 天基本看不出缓慢劣化）；
- **必须包含"出问题之前"的正常段**——系统要靠正常段建立"正常长什么样"的基线，
  只给异常段，等于让人用一把没有刻度的尺子量东西；
- 例子：问题是 9 月 28 日之后优品率下滑 → 窗口从 **9 月 20 日**（提前 8 天）取到 10 月 10 日。

### 1.2 第二步：决定导出哪几张表

| 表 | 内容 | 采样间隔 | 要求 |
|---|---|---|---|
| **主表（最重要，必须有）** | 工艺参数 + 在线质量指标（厚度、优品率等） | 1–10 分钟 | **≥1000 行**；所有列在同一个时间点同一行 |
| **化验/抽检表（强烈建议）** | 雾度、强度、热收缩、含水率等实验室数据 | 2–4 小时 | **≥100 行**，且时间点要和主表对得上（见 1.4 小技巧） |
| **事件记录（建议）** | 换网、清洗、停机、配方变更 | 不定 | 行数少没关系，**但一定要在说明文档里也用文字写一遍** |
| 产线状态/批次信息 | 批次号、规格代号、运行/降速/停机 | 随主表 | 最好直接作为主表的两三列，方便又省事 |

> **为什么化验表要"≥100 行"？** 系统的数据入口有个硬规则：**不到 100 行的表不会参与分析**
> （它只在"审计记录"里留一句说明）。所以 4 小时一次抽样时，窗口至少要 17 天；
> 21 天 × 4 小时 = 126 行，就达标了。如果实在凑不齐，就把化验结论写进说明文档，别硬凑假数据。

> **能不能只给一张表？** 能跑，但结论会弱：没有化验数据就没有"独立第二证据"，很多判断只能停在"疑似"。

### 1.3 第三步：把表整理成"系统能读"的样子

**一条一条照着改，每一条下面都写了"为什么"：**

| 要求 | ✅ 正确 | ❌ 错误 | 为什么（不这样做会怎样） |
|---|---|---|---|
| 第一行是表头，只有一行 | `时间,L3-EX-PT01,L3-GA-TH-CV01` | 有标题行、有多级表头、有合并单元格 | 系统把第 1 行当列名。多级表头/合并单元格会让列名错位，后面全乱 |
| 第一列是时间 | `时间` 或 `Timestamp` | 时间在第 9 列、或被拆成年/月/日三列 | 系统要按时间对齐多张表、算滞后关系；找不到时间列，“先后顺序”就无从谈起 |
| 时间格式统一 | `2026-09-20 08:30:00` | `46250.354`（Excel 序列号）、`2026/9/20`（无时分秒） | 序列号无法判断间隔；只有日期则所有点挤在同一天 |
| 数值纯数字 | `240.35` | `240.35℃`、`98.6%`、`1,234.5` | 带单位/百分号/千分位会被当成"文字"，无法参与任何计算 |
| 缺失留空 | 单元格空着 | 填 `-999`、`NA`、`NULL`、`0` | 系统会把这些当成真实测量值，算出不可能的极值，污染结论 |
| 一行一个时间点 | 10:00 一行、10:10 一行 | 同一时刻重复多行、或一会儿 10 分钟一会儿 1 小时混在一起 | 重复行会让统计失真；混合间隔（在同一个表里）会破坏时序计算 |
| 不隐藏行列、不留公式 | 全是"值" | 隐藏列、单元格里是公式 | 导出不完整/公式取到的是当前值而非历史值 |

**多张表怎么办？不用你手工拼！**
把同一时间轴的每张表**各存一个文件**，放在**同一个文件夹**里即可。系统会自动挑最大的那张当"主表"，
把其他对得上时间的表**自动合并**成一张宽表（这一点我们已用真实流程验证过：主表 + 化验表自动合并成功，且不产生多余行）。

> 反面提示：**不要**为了"好看"去前向填充（把上一次化验值复制到每一行）、不要做平滑、不要做重采样。
> 这些操作会造出**假信号**，让分析得出错误结论——对齐交给系统做。

### 1.4 第四步：从系统里导出（最常见的三种来源）

**从 DCS / 历史站导出**

1. 选择趋势/历史数据导出功能，勾选需要的位号（就是你平时看趋势的那些点）；
2. 时间范围按 1.1 定的窗口，采样间隔选 1 或 10 分钟（**和你们做质量报表用的间隔一致**）；
3. 导出格式选 **CSV**（如果有"CSV UTF-8"或"文本 CSV"两种，选 **UTF-8**）；
4. 导出后用 Excel 打开看一眼：第一列是不是时间、表头是不是一行（见 1.6 自检）。

**从 Excel / WPS 整理（很多同事习惯这么干）**

1. 表头只保留一行；取消所有合并单元格（选中整表 → 取消合并 → 把空出来的格子补上值）；
2. 把数值列的"单元格格式"改成**数值/常规**，去掉自定义格式里的单位和 `%`；
3. 时间列统一设为 `yyyy-mm-dd hh:mm:ss` 格式，或者干脆改成文本格式手工写成 `2026-09-20 08:30:00`；
4. 另存为 **CSV UTF-8（逗号分隔）**：Excel 里选「文件 → 另存为 → 保存类型：**CSV UTF-8（逗号分隔）(*.csv)**」；WPS 里选「另存为 → CSV（UTF-8）」。
   - ⚠️ 不要存成老的"CSV（逗号分隔）"（那是 GBK 编码）；当然，系统能自动识别 GBK，但 UTF-8 更保险。
   - ⚠️ 保存时如果弹出"保留此格式吗"，选"**是**"。
5. **化验表的小技巧**：如果化验是每 2 小时一次，请把时间点写成 `08:00:00`、`10:00:00` 这种**整点**，
   它们正好落在主表 10 分钟网格上，系统合并起来最干净（不会多出空行）。

**从 MES / 质检系统导出**：同样要求——CSV、单行表头、时间第一列、数值不带单位。

### 1.5 第五步：文件命名与摆放

```
你们按规范整理好的文件夹（示例）
L3_GP12_20260920-20261010/          ← 文件夹名：线体_产品_时间范围（不要有空格和斜杠）
├── L3_line_main_10min.csv          ← 主表（工艺 + 在线质量）
├── L3_lab_quality_2h.csv           ← 化验表
├── L3_GA_TH_PROFILE_10min.csv      ← 膜厚横向剖面（时间 × 63 个位置点，一行 = 一次扫描）
├── 工艺背景与设备说明.md             ← 说明文档①（第 2 章）
├── 异常现象与已做排查.md             ← 说明文档②（第 2 章）
└── 参数代号对照说明.md               ← 说明文档③（第 2 章）
```

- 所有要分析的文件**平铺在文件夹里**，**不要再套子文件夹**（系统只扫描这一层）；
- 文件名建议 `<线体>_<内容>_<采样间隔>.csv`，中文也可以，但不要用空格、斜杠、`\`；
- 文件夹里**不要放**内部结论/分析报告/出题答案之类的文件，避免干扰系统独立判断。

### 1.6 第六步：导出后自检（3 分钟，用 Excel + 一条命令）

**A. 用 Excel 快速看（每个人都能做）**

1. 打开 CSV：第一行是不是表头？第一列是不是时间？时间的时分秒有没有丢？
2. 随便点几个数值单元格：是数字还是文本？（文本会左对齐，数字右对齐）
3. 拉到最后一行：时间是不是连续递增、有没有重复？
4. 用"查找"搜一下 `-999`、`NA`、`NULL`：有没有拿这些当缺失值？

**B. 让系统做一次"体检"（可选，但对大文件很有用）**

把下面两条命令交给会用命令行的人（或让 AI 助手执行），只看输出里的三个词：

```
① 单表体检   → 看 "rows"（行数）和 "time_column"（是否识别出时间列）
② 文件夹体检 → 看 status 是否 ok、selected（主表选对没有）、context_files（说明文档进去没有）
```

具体命令与输出解读见 `04_运行说明/场景运行说明.md` 第 3 节。

### 1.7 如果你有剖面/图像/文字类数据

前面讲的都是"一行一个时间点、一列一个数"的数字表。但产线上还有一类数据：
**膜厚横向扫描（一次扫一整排）**、**温度场/点位图**、**衍射/CCD/热成像图片**、**操作交接班备注**。
这些也能交给系统——有一个专门的前处理步骤，先把它们变成"锚在同一根时间轴上的特征"再进分析。
给法跟数字表不一样，三种托付方式，一种一段：

**第一种：剖面数据（一次扫一排，如膜厚 时间×位置）——把整幅扫描当一张宽表**

开一个表：第一列时间（扫一次一行），后面每个测点一列，表头按 `pos_01, pos_02, … pos_48` 顺序起名。
就这么简单——系统会把"一整排"当成一幅完整扫描，算整体平均、边缘偏差、最差点位这些。
也可以给三列的"长表"（`时间,位置,值`），系统自己会转。扫不全的位置**空着，别填**；
一次扫描里有值的位置不到六成时，系统对这一次只算幅值、不算形状类特征，并在报告里如实说明。

**第二种：图像序列（衍射/CCD/热成像）——图片放文件夹 + 一张两列的索引表**

图片集中放一个文件夹（比如 `imgs/`），数据文件夹里放一张两列小表：

```
时间,文件名
2026-10-15 08:30:00,imgs/waxs_001.png
2026-10-15 12:30:00,imgs/waxs_002.png
```

文件名里本来就带时间的（像 `waxs_20261015_083000.png`），不放索引也行。
**有仪器标定文件（像 detector.json：像素尺寸、束心、距离、波长）一定一起给**：
有了它系统才可能算物理上的绝对量；没有它，系统只做整图统计（亮度、暗区占比这些）和帧与帧之间的相对比较，
并且会如实告诉你"没给标定"——它不会凭空编一个峰位出来。

**第三种：时序文字备注（操作/交接班/化验备注）——变成一张带时间的表**

就两列：`时间,备注`，一条一行；或者把记事本整理成每条前面带时间的 .md/.txt。
日期请写 `2026-09-28 06:00:00` 这样清清楚楚的——**别写 `05/07/2026` 这种分不清月日的日期**，
系统分不清时会把整份备注跳过（不猜），你记的东西就全用不上了。

**系统会自动做什么（你不用管）：**

- 把"整幅扫描"降维成一小组特征列（平均、边缘偏差、最差点位……），跟其他数据对齐到同一根时间轴上；
- 给剖面画"时间 × 位置"云图（热图），从哪天开始、从哪个位置开始不对，一眼看出；
- 把备注变成带时间的事件，跟数据排在一起看"谁先变、谁后变"。

**你必须做的（就两件）：**

- 时间列规矩跟以前完全一样：第一列、`YYYY-MM-DD HH:MM:SS`、缺失留空；
- 图像要有索引表（或文件名里带可读的时间）；**有标定文件就一起给**。

**系统不会做的（就一件）：**

- 不会替你插值补数据：扫描缺了的位置就是缺着（如实标注"稀疏"），图像没标定就算不了绝对量（只做相对比较）——
  它宁可告诉你"这个算不了"，也不会造一个看起来像真的数。

**✅/❌ 小对照：**

- ✅ 膜厚扫描：`时间,pos_01,…,pos_48`，扫不到的位置空着
- ❌ 把没扫到的位置用上一行的数填满（造数，形状特征还是假的）
- ✅ 图片：`imgs/` 文件夹 + `时间,文件名` 索引表，有 detector.json 一起给
- ❌ 一堆名字随机、没带时间的图片，也没有索引
- ✅ 备注表：`2026-09-28 06:00:00,换网一次，压力升了 0.3`
- ❌ `05/07/2026,换网`（月日不分，整份备注被跳过）

## 2. 描述文档怎么写（三份，模板在 `06_说明文档模板/`）

> **为什么一定要写文档？** 系统能看到"数字怎么变"，但**看不到"数字代表什么"**。
> 举例：同样是"北侧温度下降 2℃"，有背景说明时它能推出"横向拉伸不足 → 北边缘偏厚 → 优品率下降"这条完整证据链；
> 没有说明时，它只能报告"某列下降，与某列相关"，你拿去汇报会被问住。

**写文档的三条总原则**

1. **只写事实与背景，不写你的猜测结论**（猜测会污染系统判断；确有倾向就单独标注"未证实"）；
2. **用"段落 + 列表"写**，**不要用超过 5 行的表格**（原因见 2.4）；
3. **数字要对得上数据**（不要写"优品率跌到 95%"，而数据里最低是 96.4%）。

### 2.1 文档①《工艺背景与设备说明》：告诉它"你们厂是什么样"

**写这几块（有就写，没有就跳过）**：

1. **产线概况**：产线名称、产能、产品与规格代号、主线速、生产组织（几小时一个批次）；
2. **工艺流程与设备节点**：物料从哪走到哪，每台设备在数据里的代号前缀是什么（如 `L3-TDO` 是横拉机）；
3. **控制回路**：哪几个量是闭环控制的、设定值是多少、有没有"上限"（如加热输出上限 80%）；
4. **质量内控标准**：厚度、不匀率、雾度、热收缩率等各自的合格线（**这一条极其重要**，系统靠它判断"什么算异常"）；
5. **数据口径**：哪张表是什么间隔、单位、时区（本地时间 +08:00）；
6. **工艺常识**：你知道的物理关系，例如"拉伸区温度偏低 → 该处偏厚"、
   "定型区温度不足 → 热收缩率上升"——这些会直接变成系统的推理依据。

**例句（照这个语气写就行）**

- “横拉机（代号前缀 L3-TDO）分南北两侧独立热风闭环，两侧共用同一温度设定值 240 ℃；加热器输出可用范围 0–80 %。”
- “拉伸区风温偏低时，该处拉伸应力偏高、拉伸不足，该处厚度偏厚；南北温差会直接造成横向厚度不对称。”
- “本厂内控：厚度 12.0±0.20 μm，横向不匀率 ≤2.0 %，雾度 ≤2.0 %，热收缩率TD ≤2.0 %。”

### 2.2 文档②《异常现象与已做排查》：告诉它"出了什么事、你查过什么"

**按 5 个要素写，像写交接班记录一样：**

1. **现象（客观）**：什么指标、从什么时候开始、现在到什么水平、是"突然跳变"还是"慢慢滑"；
2. **时间线上的事件**：期间发生过什么——原料批次切换、配方/回料调整、换网清洗、停机检修、天气剧变、仪表校准；
3. **已经排查了什么**：车间/品质部做过哪些检查、结论都是"正常"（**这一条能帮系统少走弯路**）；
4. **你想让它回答什么**：1~5 个具体问题（越具体，报告越有用）；
5. **补充资料清单**：这次一共给了哪几个文件。

**例句**

- ✅ “在线优品率自 9 月 28 日起缓慢下滑（不是台阶式跳变），从 98.6% 降到 96.4%；主要不合格项是边缘厚度超差。”
- ✅ “平均厚度全程正常（11.98–12.02 μm）——**只看厚度均值发现不了问题**。”
- ✅ “9 月 27 日切换了原料批次，并按要求把回料掺入比例从 8% 提到 12%（有变更单）。”
- ✅ “已排查：挤出温度、熔体压力、露点与切片含水率、过滤器换网、冷却水温度流量、测厚仪 9 月 25 日校准——均无异常。”
- ❌ “应该是加热器老化导致的风温下降。” ← **不要写这种结论性判断**（会误导系统；如果一定要写，请另起一段写“车间初步倾向（未证实）：……”）

### 2.3 文档③《参数代号对照说明》：告诉它"每串代号是什么意思"

**最少要有两样东西：**

1. **命名规则**（一段话 + 一两个例子）：
   `L3-<设备节点>-<侧别/部位>-<功能>-<序号>`，例：`L3-TDO-N-ST-Z4-TE01` = L3线 / 横拉机 / 北侧 / 拉伸区 / 第4分区 / 温度 / 01号。
2. **每个代号一行说明**（用列表写）：
   `- 代号 = 中文名称（单位，DCS回路号，正常范围）：这句话说明它是什么物理量、影响什么。`

**写得好的关键在最后那句“物理含义”**：

- ✅ “`L3-TDO-N-Z4-HOUT01` = 北侧4区加热输出（%，回路 TIC-2404N.OUT）：闭环输出百分比；
  持续上升直至触及上限，说明加热/送风能力下降（执行器饱和特征）。”
- ❌ “北侧输出” ← 太简略，系统不知道该往哪个方向推理。

> 建议格式：把这份对照说明同时维护成一张 Excel 表（照 `03_映射文档/tag_mapping.csv` 的列填写），
> 既是给人看的，也能直接给系统读。字段含义见 `03_映射文档/映射文档编写指南.md`。

### 2.4 为什么"不要用大表格"写说明文档 —— 这条坑很隐蔽

系统的数据入口有一个判断：**Markdown 文档里超过 5 行的表格，会被当成"数据表"来处理**。
一旦被当成数据表，它就会去竞争"主表"位置；竞争不过（行数少）时，这份文档会被**排除**——
于是你辛苦写的说明文字，一个字都没进分析。

**所以：**

- 说明文字请用 **段落、列表（`- xxx`）、编号**书写；
- 只在必要时用小表格（**不超过 4 行**，例如"内控标准"三五行）；
- 代号清单**用列表写**（一个代号一行），不要为了整齐做成 60 行的大表格。

### 2.5 现成模板

`06_说明文档模板/` 里放了三份可填空模板（`模板_工艺背景与设备说明.md`、
`模板_异常现象与已做排查.md`、`模板_参数代号对照说明.md`）。
把 `【】` 里的内容替换成你们自己的，删掉用不上的小节，然后**复制进数据文件夹**即可。

## 3. 怎么用系统跑一次诊断

### 3.1 方式一：网页控制台（推荐，全程点鼠标）

**准备**：服务已启动（管理员执行一次 `ind-diag all`），浏览器打开 <http://localhost:5180>。

1. **把数据文件夹放进去**：把你们整理好的文件夹（1.5 节的那个文件夹）整体复制到系统的 `data/` 目录下，
   或直接在界面上传——点左侧 **Data** 页 → **上传文件**（也可以先 **+ 新建文件夹** 再上传，
   单个文件 ≤500 MB、一次 ≤50 个）。
2. 在 Data 页**点进这个文件夹**（此时工具栏会出现按钮），点 **分析整个文件夹**
   （如果只想分析某一个文件，点该行右侧的 **分析**）。
3. 界面自动跳到 **Analyze** 页：
   - **分析任务** 选 **深度根因诊断**（这是完整流程，适合正式分析）；
     只想快速看一眼，可选 **数据快筛**（几十分钟内给告警筛查结果）。
   - **场景名称** 起一个好认的名字，例如 `L3线优品率下滑_20260920-20261010`。
   - **提问框** 粘贴你的问题（就是从《异常现象与已做排查》第 4 节那几条）。
   - 右上角 **高级选项**（一般不用动）：报告语言选中文；本体策略保持"自动"；诊断深度保持"自动识别意图"。
4. **选一个引擎**：左侧边栏的 **执行引擎** 列表里，选一个显示"**就绪**"的引擎（例如 claude）。
   显示"**未安装**"的表示这台机器上没装好对应的命令行工具，换一个"就绪"的即可（鼠标悬停会给出说明）。
5. 点 **启动智能体分析**。右侧会**实时滚动**显示它每一步在做什么（读数据、画图、算相关性、写结论……）。
   期间可能会**暂停并提问**（例如"这列代号是什么意思"）——看到提问就在下方输入框回答，越准确越好。
6. 跑完后：点 **报告** 页，或者点结果区的 **查看完整报告**。报告有两份：
   - `report.md`：文字版诊断报告（结论、证据、建议）；
   - `diagnostic-report.html`：图表可视化版（可以直接发给领导看）。

> ⏱ 耗时参考：完整"深度根因诊断"通常几十分钟到 2 小时（取决于数据规模与所选引擎）。
> 期间可以关掉浏览器，任务在后台继续；回来在 **历史运行记录**（History）里能找到。

### 3.2 方式二：交给 AI 助手（命令行 Agent）

如果你们已经有安装本项目的 AI 助手（Claude Code / OMP / ZCode 等），只要对它说一句话：

> 对 `data/L3_GP12_20260920-20261010` 做工业深度诊断，目标是定位优品率下滑的主导原因，
> 使用 industrial-analysis-auto 技能，按完整流程执行。

然后按提示回答它的问题即可。它会把运行产物写到 `workspace/diagnostic-runs/<时间戳>_<场景名>/`。
详细的字段说明与排查见 `04_运行说明/场景运行说明.md`。

### 3.3 报告怎么读（3 个要点，避免误读）

1. **看结论的"三态"**：
   - **DETERMINED（已定论）**= 证据充分，可以执行处置；
   - **COMPETING_SET（仍有两个以上候选分不开）**= 现有数据不足以区分，报告会告诉你**缺哪个数据**；
   - **NEEDS_DATA（需要补数据）**= 先按"补测建议"采数据，再跑一次。
2. **看证据等级（L1–L7）**：L1 是直接测量（最硬），越往后越弱（L7 是假设）。
   报告的结论强度**以最弱的那条证据为准**——如果结论挂着 L6/L7，请谨慎采信。
3. **看置信度数字**：60 分以下表示"只能算线索"，不要据此大动设备；
   报告末尾的**补测建议**往往是最省钱的下一步。

## 4. 为什么必须按这个要求做（一条条讲清后果）

| 你的做法 | 系统内部会发生什么 | 你的损失 |
|---|---|---|
| 时间列不规范（序列号/只有日期/没有时间列） | 无法建立时间轴，只能用"第 1 行、第 2 行"的序号轴 | **所有"先后/滞后"结论失效**——而工业诊断最核心的证据就是"谁先变、谁后变、滞后多久" |
| 数值带单位或 `%` | 该列被判为"文字"列 | 这一列不参与相关性、趋势、异常计算，等于白导 |
| 缺失填 `-999` | 被当成真实测量值参与统计 | 出现不可能的极值，可能把系统引向完全错误的方向 |
| 用合并单元格 / 多级表头 | 列名错位 | 后面的映射、统计、报告全部对不上号 |
| 只给平均值，不给分布/边缘/极差指标 | 系统只看到"均值正常" | **发现不了"均值正常但分布劣化"这类问题**（本模板样例正是这种；这类问题在产线里非常常见） |
| 只给实际值，不给**设定值/闭环输出** | 无法判断"是人为调了参数"还是"设备能力变了" | 容易把"操作调整"误判为"设备故障"，或反过来 |
| 给的数据没有正常段（只给异常段） | 没有基线可比 | 只能"看数字大小"，说不清"偏了多少、从哪天开始偏" |
| 化验/低频表不足 100 行 | 不进入分析主表 | 化验证据链断裂，结论只能停在"疑似" |
| 说明文档写成大表格 / 写成结论猜测 | 文档被排除 / 干扰系统判断 | 你的现场知识用不上，报告变成"通用统计学分析" |
| 代号不写映射 | 系统只能按数值特征猜 | 报告里出现"某未命名列"，无法定位到设备与工位，无法落地整改 |
| 分侧/分区测点缺失 | 看不到"南北不对称""单侧异常" | 无法区分"整机/环境因素"与"局部设备因素"，常导致误判（如把单侧加热器问题误判为环境降温） |

**一句话总结**：系统不是"越神秘越厉害"，它靠的是**你给的信息 + 它自己的推断**。
你给的每一条约束（时间、单位、代号含义、内控标准、现场事实），都会变成它推理链上的一环。

## 5. 常见问题（FAQ）

**Q1：我完全不懂编程，能用吗？**
能。全程只需要"导出 CSV / 打字 / 点鼠标"。第 3.1 节那六步就是全部操作。

**Q2：数据涉密（代号、配方、工艺参数），安全吗？**
分析程序在本机/内网运行，数据文件保存在本机磁盘。但要注意一点：
**如果选择的是"云端大模型"引擎，分析过程中会有数据片段（列名、样本值）被发送给模型服务商。**
对涉密数据，请让管理员选择本地/私有部署的引擎，或与管理员确认公司的大模型使用规范。
（你们用代号当表头本身就有一定"脱敏"效果，但配方数值仍在数据里。）

**Q3：表头必须用中文吗？必须叫某个固定名字吗？**
不必须。代号、英文、缩写都可以，**但必须有对照说明**。唯一要固定的是**时间列**建议叫 `时间`（或 `Timestamp`/`时间戳`）。

**Q4：只有 EXCEL 可以吗？没有 CSV。**
可以（支持 `.xlsx/.xlsm/.xls`）。但请保证：**只有一个表头行、没有合并单元格、没有公式**；
如果是多 sheet 工作簿，系统会挑数据量最大的那个 sheet，建议把 sheet 名起成和文件一样的名字。

**Q5：我就想分析一张表，可以不管文件夹吗？**
可以——在 Data 页点某个文件右侧的 **分析**。但这样不会带入化验表与说明文档，结论会弱一些。

**Q6：数据太长了（几个月、上百万行）怎么办？**
先按"分析窗口"裁剪到 **7–21 天**。系统对超过 10 万行的文件只做抽样统计，长窗口反而稀释异常信号。

**Q7：没有化验室数据行不行？**
行，但要接受"证据单一"：工艺与在线质量能定位工艺侧原因，涉及材料/结晶/力学性能的判断会打折扣。

**Q8：报告说 COMPETING_SET（候选没分开）、置信度只有 50–60，是不是系统不行？**
不是。这是**诚实的表达**：它明确告诉你"这两个原因用现有数据分不开，需要补哪一类数据"。
补上报告"补测建议"里的数据再跑一次，通常就能定论。系统不允许自己在证据不足时下结论（这也是它能被信任的原因）。

**Q9：跑一次要多久？能中途关电脑吗？**
几十分钟到 2 小时（看数据量和引擎）。关掉浏览器不影响任务（在服务器上继续跑）；关掉服务器进程才会中断。
中断了可以在 History 里继续。

**Q10：系统问我的问题看不懂/答不上来怎么办？**
尽量如实回答"不知道/需要问设备科"——它会按"信息不足"处理并降低置信度，而不是乱猜。
如果你当场能查到（例如某代号的含义），告诉它，结论质量会明显提升。

**Q11：我已经把多张表拼成一张大宽表了，还要按你们的方式吗？**
不用重做。系统识别到"已对齐的宽表"会**优先直接使用它**，你的工作不会白费。只要保证这份宽表本身符合第 1.3 节的要求即可。

**Q12：报告里提到"需要补充数据"，一般补什么？**
最常见的是三类：① 缺失的测点（如另一侧的对应测点、设定值/输出）；② 时间上更靠前的正常段；
③ 独立第二证据（化验、离线检测、检修记录）。补哪一类取决于报告里的"补测建议"。

## 附录 B：名词小词典

| 词 | 通俗解释 |
|---|---|
| **DCS / 历史站** | 工厂里记录所有仪表数据的系统；你们平时看"趋势图"的地方 |
| **位号 / 代号 / Tag** | 每个测点在系统里的唯一名字，如 `L3-EX-PT01`（3号线主挤出机压力） |
| **映射文档** | "代号 → 中文名/单位/设备/物理含义"的对照表，是系统理解数据的字典 |
| **本体（Ontology）** | 系统把"设备、参数、质量指标、它们之间的物理关系"结构化后的知识模型；有了它才能做因果推理 |
| **PV / SV / OP** | 实际值（测量值）/ 设定值 / 输出百分比（闭环控制器输出）；三者对比能区分"人为调参"与"设备能力变化" |
| **稳态 / 非稳态** | 正常匀速生产（稳态）vs 升降速、换网、停机（非稳态）；系统只在稳态段做统计，避免误报 |
| **时滞 / 滞后** | 一个指标变化后，另一个指标隔一段时间才响应（如风温下降 6 小时后优品率才吃亏） |
| **混杂因素** | 同时影响"原因"和"结果"的第三方因素（如季节降温、回料比例上调），不排除它就会张冠李戴 |
| **竞争假设** | 系统同时考虑多个可能原因，用数据把不能解释现象的逐个排除，最后留下能解释的那个 |
| **置信度 / 证据等级** | 结论的可信程度（0–100）与证据硬度（L1 直接测量最硬，L7 假设最软） |
| **补测建议** | 系统告诉你"还想进一步确认，需要补哪份数据"——通常是最省钱的下一步 |
