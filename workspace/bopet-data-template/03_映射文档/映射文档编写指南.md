# 映射文档编写指南（代号 → 语义）

映射文档要回答一个问题：**"这串只有本厂看得懂的代号，到底是什么？"**
分析系统不认识 `L3-TDO-N-ST-Z4-TE01`，只有你告诉它，它才能把统计学上的"某个列在下降"翻译成
"横拉机北侧拉伸区 4 区风温在下降，且南侧不变" → 这才是能定案的证据。

本包用三种形式承载同一份映射，产线**只需维护其中 CSV 一份**，其余两种可由它派生：

| 文件 | 面向 | 用途 | 是否必须 |
|---|---|---|---|
| `03_映射文档/tag_mapping.csv` | 产线工程师（Excel 打开） | **源头**：新增/修改测点在这里改 | ✅ 必须维护 |
| `03_映射文档/tag_mapping.json` | 分析系统 / 工具链 | 机器可读的同一份映射（字段完整） | ✅ 随 CSV 一并更新 |
| `03_映射文档/L3_bopet_ontology.json` | 分析系统（进阶） | 预构建本体：含参数角色、因果关系、混杂因素，已通过 schema 校验 | 可选 |
| `02_data/参数代号对照说明.md` | 分析系统（背景知识） | 说明命名规则与代号含义（用列表书写，**不要用大表格**） | ✅ 建议 |

## 一、字段定义（tag_mapping.json / csv 同义）

| 字段 | 含义 | 是否必填 | 示例 |
|---|---|---|---|
| `code` | 数据表表头的**原始代号**，逐字一致（含大小写与连字符） | ✅ | `L3-TDO-N-ST-Z4-TE01` |
| `name` | 中文名称（唯一权威解释） | ✅ | TDO北侧拉伸区4区热风温度 |
| `unit` | 单位（数据本身不带单位，单位写在这里） | ✅ | ℃ |
| `stage` | 所属工段 | ✅ | 横向拉伸(TDO) |
| `equipment` | 设备节点代号 | ✅ | L3-TDO |
| `loop` | DCS/PLC 回路号或位号（便于现场核对） | 建议 | TIC-2404N |
| `role` | 角色：process(工艺) / quality(质量) / control(控制) / env(环境) / meta(元数据) | ✅ | process |
| `target` | 目标值 / 设定值 | 建议 | 240.0 |
| `normal_range` | 正常范围（下线/上线），用于异常判定 | ✅ | [239.6, 240.4] |
| `sampling` | 采样间隔 | 建议 | 10min |
| `physical_meaning` | **物理含义**：这个量代表什么、影响什么（最关键的一栏） | ✅ | 决定该侧 PET 取向与横向厚度分布 |
| `governing_law` | 相关物理规律/方程（没有可写 ——） | 建议 | Avrami 结晶动力学；热收缩 ∝ (T-Tg) 热历史 |
| `setpoint` | 控制量专用：设定值 | 控制量必填 | 240.0 |

## 二、写作正反例

**好的 `physical_meaning`（有物理链条、可检验）**

- 横向拉伸主拉伸区（第4分区）北侧热风实际温度，决定该侧 PET 取向与横向厚度分布
- 加热器输出百分比。闭环输出持续上升直至触及上限，说明加热/送风效能下降（执行器饱和特征）

**差的写法**

- "北侧温度" —— 看不出影响什么，无法支撑因果推断
- "重要参数" —— 无信息量
- 直接把设备手册整段抄进来 —— 抓重点，一行为宜

**正反例（代号与表头不一致）**

- 数据表头写 `TDO_N_Z4_T`，映射表写 `L3-TDO-N-ST-Z4-TE01` → ❌ 系统无法对应，该列只能靠统计猜
- 数据表头写 `L3-TDO-N-ST-Z4-TE01`，映射表同样 → ✅

## 三、维护规则

1. **新增测点**：在 CSV 追加一行（同时补 json），再导出数据；
2. **代号变更**：改映射表的同时，必须保证数据表头同步（建议旧代号保留一行并注明"已废弃，见 XXX"）；
3. **删除测点**：映射表可保留该行（历史数据仍可解释）；
4. **不要出现"未映射"的列**（除非确实无意义）：系统对无映射的列会明确标注"含义未知，仅作统计参考"，
   这会降低结论置信度；
5. 映射表里**不要写结论/猜测**（如"此值下降是加热器老化导致"）——只写"这个量是什么"。
   带有诊断性判断的内容请写在《异常现象与已做排查.md》并明确标注"未证实"。

## 四、与"预构建本体"的关系（进阶，可选）

`L3_bopet_ontology.json` 是本模板附带的**机器可读本体**：除了代号映射，还包含

- 参数角色（target/predictor/confounder/control）、
- 设备-工段归属、
- **因果关系**（14 条：含机理、预期时滞、方程、函数形式）、
- **已知混杂因素**（4 条：环境温度、回料比例、过滤器压差、循环水温）。

它已通过 `ontology_schema.json` 校验，可直接作为分析的先验知识使用；不需要它时忽略即可——
系统会自己从数据 + 说明文档构建本体。产线**不需要维护这个文件**（它由 `05_生成脚本` 从映射表派生）。
