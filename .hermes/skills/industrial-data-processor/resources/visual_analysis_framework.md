# VLM Visual Image Analysis Framework

## Core Idea

An image is not a passive "evidence display" but an **active input source** for diagnostic reasoning. By reading images the VLM Agent obtains three classes of insight that cannot be obtained from numbers alone:

1. **Temporal alignment insight**: the synchrony of fluctuations across several parameters on one shared time axis — who changes first? who changes later? who changes together?
2. **Spatial pattern insight**: nonlinearity, clustering, and anomalous regions visible to the eye in a scatter plot
3. **Event association insight**: the visual change before and after an event marker — does quality step? by how much?

## Design Principles

### Charts must be designed for the VLM

| Design element | Why it matters | How to implement |
|---------|-----------|---------|
| **Shared time axis** | The VLM judges temporal relations between parameters from aligned time ticks | All time series use the same x-axis |
| **Parameter normalization** | Parameters with different units cannot be compared on one scale | z-score normalization, or min-max onto [0,1] |
| **Event marker lines** | The VLM can see "did the parameter change markedly when the event occurred" | Red dashed line + text annotation |
| **Color-coded grouping** | The VLM can see whether data from different groups forms separate clusters | A different color per group |
| **Anomaly interval shading** | The VLM can see whether anomalies concentrate in a particular period | Red semi-transparent shading |
| **Large fonts + high contrast** | The VLM needs clearly legible labels | Font ≥ 12pt, high-contrast background |

### Key chart type: temporal alignment overlay (generate first when a time column exists)

This is the chart type from which the VLM extracts the most diagnostic information, and it is **the primary chart the Data Processor should generate first whenever a valid time column exists**. When the data has a usable time column, the key quality indicators and key process parameters should be drawn **in the same figure**, aligned on **the same x time axis**. Normalize all parameters and overlay them on one time axis:

```
Y-axis: normalized value (z-score)
X-axis: time (shared)

         conversion_pct (blue solid)
         reactor_temp_C  (red dashed, reversed)
         cooling_duty_kW (green solid)
         byproduct_ppm   (orange dashed, reversed)
    1.5 ┤ ╭─╮
        │/   ╲
    1.0 ┤      ╲  ← early stable region
        │        ╲
    0.5 ┤         ╲ ╭──→ conversion declining
        │          ╲╱
    0.0 ┤           ╲
        │  ╲         ╲
   -0.5 ┤   ╲         ╲
        │    ╲         ╲  ← synchronized-trend region (all parameters move together)
   -1.0 ┤     ╲         ╲
        │      ╲         │╲ ← regen event (red dashed line)
   -1.5 ┤       ╲       │  ╲ ← partial recovery
        │        ╲      │   ╲
   -2.0 ┤         ╲_____│____╲
        └────────────────┴────── time →
```

From this chart the VLM can read directly:
- "the blue and green lines decline in synchrony — one mechanism"
- "the red line (temperature) rises — an inverse relation"
- "there is a clear step at the red dashed line — event association"
- "after the event it recovers but does not return to the initial level — partial recovery"

### Requirements for the primary chart (only applies to data with a time column)

This primary chart must satisfy the following rules:

1. **Put several key parameters in one figure**; do not split each parameter into completely independent, mutually unaligned figures.
2. **All curves use the same x-axis**, and this requirement is premised on the existence of a valid time column; prefer real time, and do not mechanically fabricate a "temporal alignment" when there is no time column.
3. **At minimum it must contain**:
   - the main quality target
   - the top candidate cause parameters
   - key event markers
   - identification of anomalous or degradation intervals (if any)
4. **Normalize before overlaying**, to keep differences of units from masking temporal relations.
5. If there are too many series, it is acceptable to keep only the 8-12 most critical lines, but "quality target + candidate causes + events" must all appear in the same primary chart.
6. This chart should be the **first chart read** in the subsequent visual analysis.
7. If the data **has no valid time column**, do not mechanically generate a pseudo time-aligned chart. Explicitly declare that "temporal alignment is not applicable" and switch to the strongest non-temporal charts (stratified scatter, grouped box plot, distribution comparison, before/after event comparison, etc.).

## Phase 5.5: Visual Image Parsing Protocol

After generating all charts and before writing image_captions, execute the following protocol:

### Step 1: Read each chart one by one (VLM looks directly at the PNG)

For every PNG image in `03_figures/`, use the Read tool to read the image file directly.

**Reading-order requirements:**
1. If a valid time column exists, read the "primary temporal alignment overlay" first
2. From the primary chart, first extract the synchronous groups, leading/lagging leads, and event response windows
3. Then read scatter plots, event response charts, Simpson charts, heatmaps, etc., to confirm or refute the visual judgement from the primary chart
4. If no valid time column exists, start from the strongest non-temporal overview chart

**The VLM must answer the following questions when reading each chart**:

| Question | Applies to which charts | Expected insight |
|------|------------|-----------|
| **Temporal synchrony**: which parameters fluctuate in synchrony? Which comes first? | Time series charts, alignment overlays | Causal-temporal leads |
| **Event response**: at the event marker, which parameters step markedly? In which direction? By how much? | Charts with event markers | Root-cause confirmation/exclusion |
| **Clustering/stratification**: do data points of different colors form separate clusters? Is the slope consistent within a cluster? | Scatter plots (colored by group) | Simpson Paradox detection |
| **Nonlinearity**: are there visible inflection points or threshold effects in the scatter plot? | Scatter plots | Physical threshold identification |
| **Trend morphology**: is the decline linear or accelerating? Are there inflection points? | Trend charts, degradation curves | Degradation-mode classification |
| **Anomaly clustering**: do anomaly points cluster in a particular period? | Time series annotated with anomalies | Leads on the origin of anomalies |
| **Direction consistency**: do several quality indicators degrade in the same direction? | Multi-indicator time series | Mechanism-consistency verification |

### Step 2: Extract structured visual insight

Structure the VLM's observations into `visual_analysis.json`, where each chart entry contains:

- `synchronous_groups`

- a synthesis paragraph explicitly stating "which root-cause hypotheses this co-axially aligned chart supports/weakens, and why"

### Step 3: Generate image_captions.json (compatibility layer)

Extract the key information from `visual_analysis.json` and generate the compatibility-format `image_captions.json` for downstream Agents that do not use the VLM.

### Step 4: Hand over to the Diagnostician

`visual_analysis.json` becomes a **required reading** for Diagnostician Phase 0. The visual insight it provides is richer than numbers alone:

| What numbers alone tell the Diagnostician | What visual analysis tells the Diagnostician in addition |
|:---|:---|
| conversion and cooling_duty r=0.880 | "the two parameters decline in almost perfect synchrony in the chart, with no visible lag — one mechanism" |
| Simpson Paradox in CAT-A-regen with r=-0.545 | "the slope direction of the orange points (post-regeneration) is exactly opposite to the blue points (pre-regeneration) — a direction reversal visible to the eye" |
| pre-regeneration conversion mean 78.2%, post-regeneration 73.8% | "there is an upward step of about 5% at the regeneration event, but far below the initial 95% — the visual impression of partial recovery is very clear" |
| trend attenuation 44.8% | "after detrending the scatter is visibly more dispersed and the correlation weaker — visual confirmation that the attenuation is not trivial" |

## Chart Design Specifications

### Temporal alignment overlay (the most important VLM input)

```python
# Design points:
# 1. Normalize all key parameters onto one scale (z-score)
# 2. Shared x-axis (time) — only applicable when a valid time column exists
# 3. Several quality indicators and several key process parameters must appear together in the same figure
# 4. Reverse parameters negatively correlated with quality (such as temperature) so that all parameters move in the same direction
# 5. Event markers as red dashed lines + text annotations
# 6. Anomalous intervals as red shading
# 7. Legible legend, font ≥ 12pt
# 8. Y-axis label: "Normalized Value (z-score, negative correlations reversed)"

def generate_vlm_temporal_overlay(df, targets, key_params, events, fig_dir):
    """
    Generate a VLM-readable temporal alignment overlay.

    Key design:
    - Reverse negatively correlated parameters so that all lines "move together"
    - Event markers clearly visible
    - Anomalous intervals shaded
    """
    fig, ax = plt.subplots(figsize=(18, 8))
    
    for col in targets + key_params:
        values = (df[col] - df[col].mean()) / df[col].std()
        # reverse the direction if negatively correlated with the primary quality target
        if correlation_sign(col, primary_target) < 0:
            values = -values
            label = f"{col} (reversed)"
        else:
            label = col
        ax.plot(df['timestamp'], values, linewidth=1.0, label=label, alpha=0.8)
    
    # event markers
    for event_time, event_name in events:
        ax.axvline(event_time, color='red', linestyle='--', linewidth=2, alpha=0.8)
        ax.text(event_time, ax.get_ylim()[1]*0.95, event_name,
                rotation=90, va='top', ha='right', fontsize=11, color='red', fontweight='bold')
    
    ax.set_xlabel('Time', fontsize=13)
    ax.set_ylabel('Normalized Value (z-score, negative correlations reversed)', fontsize=12)
    ax.legend(fontsize=10, loc='upper right')
    ax.set_title('Temporal Alignment — All Parameters Normalized & Direction-Aligned', fontsize=14, fontweight='bold')
    ax.grid(True, alpha=0.3)
    fig.savefig(fig_dir + '/fig_vlm_temporal_overlay.png', dpi=150, bbox_inches='tight')
```

### Simpson Paradox visualization (VLM-specialized)

```python
# Design points:
# 1. Two subplots side by side (CAT-A vs CAT-A-regen)
# 2. Distinguish groups by color within each subplot
# 3. Use thick lines for regression lines so the direction is obvious at a glance
# 4. Annotate the r value and the p value
# 5. Write the title in large type: "SIMPSON PARADOX" or "consistent direction"
```

## VLM Image Dispatch Rules — Not All Images Go to VLM

### Core Principle

**Only spatio-temporally aligned images carry VLM diagnostic value.** VLM excels at reading cross-parameter synchrony, temporal precedence, event response, and group separation from images. Single-parameter trend charts, bar charts, and non-aligned dual-axis plots do NOT benefit from VLM analysis — the diagnostician can read the same information faster from numbers.

### Image Filtering Rules

| Image Type | VLM Priority | Rationale |
|-----------|-------------|----------|
| Multi-param temporal overlay (z-score normalized, shared time axis) | **MANDATORY** | VLM reads synchrony groups, precedence signals, event response, trend morphology |
| Per-group temporal overlay (colored by confounder) | **MANDATORY** | VLM reads group-specific degradation patterns, Simpson check |
| Scatter colored by confounder with regression lines | **SUPPLEMENTARY** | VLM reads cluster separation, within-group slope direction |
| Event response overlay (before/after event) | **SUPPLEMENTARY** | VLM reads response magnitude, recovery completeness |
| Single-parameter time series | **NOT_FOR_VLM** | No cross-parameter insight. Diagnostician reads trend from numbers |
| Bar chart (correlation comparison) | **NOT_FOR_VLM** | VLM cannot read numerical r values from bar heights |
| Dual-axis time series (2 params only) | **NOT_FOR_VLM** | Too few parameters for meaningful pattern detection |
| Histogram / distribution plot | **NOT_FOR_VLM** | Statistical shape not useful for root cause visual diagnosis |

### Dispatch Protocol

1. Generate VLM-specialized temporal overlay chart (`fig_vlm_temporal_overlay.png`) using design specs above
2. Generate `vlm_input_manifest.json` that lists only MANDATORY + SUPPLEMENTARY images
3. Write skeleton_pre_vlm as fallback
4. Dispatch vlm-visual-analyzer — it MUST read `vlm_input_manifest.json` FIRST to know which images to read
5. After VLM completes, verify that chart_inventory only contains images from vlm_input_manifest

Diagnostician Phase 0 additionally reads `visual_analysis.json`:

```
Phase 0 addition:
  03_figures/visual_analysis.json  ← VLM visual analysis result
  ├── visual_observations[]        ← visual insight per chart
  ├── cross_parameter_temporal_alignment ← temporal alignment analysis
  │   ├── synchronous_groups[]     ← synchronous parameter groups
  │   ├── precedence_signals[]     ← signals of who changed first
  │   └── independent_parameters[] ← independent parameters
  └── synthesis                    ← overall visual conclusion
```

In Phase 3 candidate screening the Diagnostician additionally uses the visual insight:

```
Screening rules addition:
  IF visual_analysis.cross_parameter_temporal_alignment.synchronous_groups contains a parameter group
  AND the correlation of the parameters in that group with the quality target is verified by validate_report
  THEN flag it as "visually confirmed same-mechanism parameter group"
  
  IF for some parameter in visual_analysis event_response.recovery_completeness == "partial"
  THEN flag it as "visually confirmed partial recovery — catalyst-related"
  
  IF for some parameter in visual_analysis event_response.parameters_did_not_respond contains that parameter
  THEN that parameter is unrelated to the event; demote it as a root-cause candidate
```
