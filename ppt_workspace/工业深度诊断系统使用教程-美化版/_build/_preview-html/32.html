排错速查：三个等级，按顺序查
九成问题落在这三类里。先看现象，再看处理办法，不用猜
先查 L1，再查 L2
等级现象怎么处理
L1 起不来打开 localhost:5180 打不开先跑 ind-diag status，看哪一行不是 running；再去 .runtime/ 看对应日志
L1 起不来命令一直不返回，最后报超时多半是漏了 --detach；服务其实已起来，直接 status 确认即可
L1 起不来RAG 引擎起不来确认 Python ≥ 3.10；网络慢就先切镜像源再 uv sync
L2 跑不起来点开始诊断没反应，或立刻失败多半是引擎 CLI 未登录：跑一次 <引擎> --version 确认，缺 Key 就补 .env
L2 跑不起来接口返回 400 HARNESS_UNKNOWN引擎名拼错了；在前端左下角的下拉里选，不要手写
L2 跑不起来接口返回 409 HARNESS_UNAVAILABLE这个引擎本机没装；换一个绿点的，或先装它的 CLI
L3 结果不对结论是 COMPETING_SET，分数不高这不是失败：数据不足以区分假设。页面会列出最小判别数据集，补采那一列即可
L3 结果不对报告没生成，任务停在中间查看该运行的 .pipeline_events.jsonl，确认执行到哪一步停下
三组已按「先看现象 → 再定位」的顺序排好
