关键结论（供复用）：

### 输入格式契约
- 输入 = 单个文件 **或** 整个文件夹（混合格式）。支持 `.csv/.tsv/.txt/.dat`（分隔符投票+编码回退 utf-8→gb18030→latin-1）、`.xlsx/.xlsm/.xls`（多 sheet 评分，同名 sheet 优先，≥100 行可跨表按同名列外连接合并）、`.json`（records / {data:[]}）、`.md`（管道表）、`.html`（正则提表）。二进制/图片/脚本 → 跳过并记原因。
- 归一化输出：`00_input/preprocessed_data.csv`（utf-8-sig）+ `.json` 兜底 + `preprocessing_report.json` 审计 + `context/` 保留非表格文件。
- 归一化规则：列名去空白/去重（`_2`）/丢全空列；时间列按名称提示 + datetime 可解析性检测（数值列永不误判为 epoch）；时间统一 ISO；缺失保持 NaN。
- 硬性数据门槛（各 skill 不同）：deep-diagnosis 无硬门槛但 >100K 行抽样；line-stability **≥50 行**且需可解析时间列（否则 not_assessable）；sentinel watch 1k–100k 行、fast-screen 1–500 行且需 baseline；doe 需数值列且非零方差；tuning-memory 基线 ≥10 有效点、效果段 ≥2 点。
- 时间列是**事实上的必需项**（除 doe designed 模式）。
- `run_config.json` 必填 `data_path`；可选 ontology_path / reference_dir / process_description / batch_id / user_objective / known_faults / interaction_mode(auto|interactive|minimal) / analysis_constraints(时间范围/聚焦列/排除列/judge 阈值/三个迭代上限)。

### 六条作业路径（analysisIntent）
`deep-diagnosis`(默认,9阶段) / `stability-report` / `quick-screen` / `doe-analysis` / `experience-mining` / `optimizer-campaign`。
- 仅 deep-diagnosis 由 LLM agent 驱动；其余 5 条为确定性脚本为主（零 LLM 或 agent 只解读）。
- 对外契约：`POST /api/external/v1/analyze`，`GET /v1/capabilities` 返回 intents + harnesses。

### skill 设计质量结论
优秀点：单一事实源（.claude/skills 唯一源 + 镜像生成器 + drift guard）、确定性脚本算数/agent 只解读、质量门以退出码裁决、诚实降级（not_assessable/not_estimable 是合法结果）、复用而非重造（sentinelcore 被 stability 复用；doestats 被 optimizer 复用）、工件可复算（sha256+行范围+方法清单）。
不足：skill 间耦合深（stability 协同 sentinel/tuning/doe 三条腿）、输入门槛不统一（50/100/1k 行三套）、时间列隐性必需但文档未集中声明、fast/full 双模式增加维护面。
